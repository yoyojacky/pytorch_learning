## 核心概念讲解

### 为什么要把数据分成三份？

想象你在准备一场考试：

- **训练集（train set）**是你的练习册，模型天天在上面做题、对答案、改错（更新参数）；
- **验证集（validation set）**是模拟考，每学完一段时间就考一次，用来判断"现在的学法有没有效"，并据此决定要不要保存当前这个版本的模型。注意：模型不会在模拟考的卷子上改错，它只是被考；
- **测试集（test set）**是真正的高考，只在最后考一次，用来给出最终成绩。它绝对不能参与训练，也不能参与"选哪个版本最好"的决策，否则成绩就不真实了。

如果只分训练/测试两份，你就会忍不住用测试集去挑模型，相当于提前偷看了高考试卷，最终成绩会虚高。本章按 400 / 100 / 100 切分 600 个样本。

### epoch 和 batch

- **batch（批次）**：一次喂给模型的一小撮样本。本章训练加载器 `batch_size=32`，即每次喂 32 条。
- **epoch（轮）**：把整个训练集完整过一遍叫一轮。本章训练 30 轮，即把 400 条训练样本整体学了 30 遍。每轮内部有 400 ÷ 32 = 12.5，即 13 个批次（最后一批只有 16 条）。

### 训练五步曲

PyTorch 里更新一次参数固定是五步：

```
算损失 loss = criterion(model(x), y)   # 前向传播 + 计算差距
optimizer.zero_grad()                  # 清空上一轮残留的梯度
loss.backward()                        # 反向传播，算出每个参数的梯度
optimizer.step()                       # 按梯度更新参数
```

（前两行合起来常写成一步，所以习惯叫"五步曲"或"四步曲"都可以，关键是顺序不能乱。）

### train() 与 eval()、no_grad()

- `model.train()`：告诉模型"现在是上课学习时间"。有些层（如 Dropout、BatchNorm）在训练和测试时行为不同，这个开关就是给它们看的。本章的网络虽然没有这些层，但养成"训练前先 train()、评估前先 eval()"的习惯，换到复杂网络时就不会踩坑。
- `model.eval()`：告诉模型"现在是考试"，请保持稳定输出。
- `torch.no_grad()`：评估只是"对答案"，不需要改错，也就不需要记录梯度。用它包住评估代码，PyTorch 就不去构建计算图，省内存、速度快。

### 交叉熵损失与 Adam

- **交叉熵损失 `CrossEntropyLoss`**：分类问题的标准"打分器"。模型输出各类别的得分（logits），它负责衡量"正确类别的得分够不够高"，差距越大损失值越大。内部自带 Softmax，所以网络最后一层**不需要**自己加激活函数。
- **Adam 优化器**：一种自适应学习率的参数更新算法。相比最基础的 SGD，它会为每个参数自动调节步子大小，绝大多数情况下收敛更快、更稳，是实战中的默认选择。

### state_dict：模型的"存档"

`model.state_dict()` 是一个字典，装着模型所有参数的当前数值。`torch.save` 把它存成文件（本章存为 `best_model.pt`），以后用 `torch.load` 读回来、再 `model.load_state_dict` 灌进模型，模型就恢复到了存档那一刻的水平。本章的策略是：**每当验证准确率刷新历史纪录，就覆盖保存一次**，训练结束后加载这份"巅峰存档"去考测试集。

## 完整代码

```python
"""
第 5 章：完整训练流程 —— 训练/验证/测试 + 模型保存与加载
对应赛项知识点：对复杂的智能系统进行测试和训练并编写报告；
实现模型精度与效率平衡
"""
import torch  # 导入 PyTorch
import torch.nn as nn  # 神经网络模块
from torch.utils.data import DataLoader, TensorDataset, random_split  # random_split 随机划分数据集

torch.manual_seed(42)  # 固定随机种子

# ========== 1. 构造数据并做三路划分：训练/验证/测试 ==========
n = 600  # 600 个样本
X = torch.randn(n, 4)  # 4 个特征
y = ((X[:, 0] * 2 - X[:, 1] + X[:, 2]) > 0).long()  # 由特征线性组合决定的二分类标签

dataset = TensorDataset(X, y)  # 打包成数据集
train_set, val_set, test_set = random_split(dataset, [400, 100, 100])  # 按 400/100/100 随机切分

train_loader = DataLoader(train_set, batch_size=32, shuffle=True)  # 训练加载器：打乱
val_loader = DataLoader(val_set, batch_size=32)  # 验证加载器
test_loader = DataLoader(test_set, batch_size=32)  # 测试加载器

# ========== 2. 定义模型 ==========
class Classifier(nn.Module):  # 定义分类网络
    def __init__(self):  # 构造函数
        super().__init__()  # 调用父类构造
        self.net = nn.Sequential(  # Sequential 把多层按顺序串成一个整体
            nn.Linear(4, 32),  # 输入层 4 -> 隐藏层 32
            nn.ReLU(),  # 非线性激活
            nn.Linear(32, 16),  # 隐藏层 32 -> 16
            nn.ReLU(),  # 非线性激活
            nn.Linear(16, 2),  # 输出层 16 -> 2 个类别
        )

    def forward(self, x):  # 前向传播
        return self.net(x)  # 数据依次流过 Sequential 中各层

model = Classifier()  # 实例化模型
criterion = nn.CrossEntropyLoss()  # 交叉熵损失
optimizer = torch.optim.Adam(model.parameters(), lr=0.01)  # Adam 优化器（比 SGD 更常用）

# ========== 3. 评估函数：在任意加载器上计算准确率 ==========
def evaluate(model, loader):  # 定义通用评估函数
    model.eval()  # 切换到评估模式（关闭 Dropout/BN 的训练行为）
    correct, total = 0, 0  # 计数器：预测正确数、总样本数
    with torch.no_grad():  # 评估不需要梯度
        for bx, by in loader:  # 逐批次评估
            pred = model(bx).argmax(dim=1)  # 取得分最高的类别作为预测结果
            correct += (pred == by).sum().item()  # 累加预测正确的数量
            total += len(by)  # 累加样本总数
    return correct / total  # 返回准确率

# ========== 4. 训练 + 每轮验证 ==========
best_val_acc = 0.0  # 记录历史最佳验证准确率
for epoch in range(30):  # 训练 30 轮
    model.train()  # 切换到训练模式（与 eval 对应）
    for bx, by in train_loader:  # 训练循环五步曲
        loss = criterion(model(bx), by)  # 前向 + 算损失
        optimizer.zero_grad()  # 清梯度
        loss.backward()  # 反向传播
        optimizer.step()  # 更新参数

    val_acc = evaluate(model, val_loader)  # 在验证集上评估
    if val_acc > best_val_acc:  # 如果验证准确率创新高
        best_val_acc = val_acc  # 更新最佳记录
        torch.save(model.state_dict(), "best_model.pt")  # 保存当前最优模型的参数
    if (epoch + 1) % 10 == 0:  # 每 10 轮打印
        print(f"第 {epoch+1:2d} 轮 | 验证准确率={val_acc:.2%} | 历史最佳={best_val_acc:.2%}")

# ========== 5. 加载最佳模型并在测试集上出最终报告 ==========
model.load_state_dict(torch.load("best_model.pt"))  # 把保存的最优参数载入模型
test_acc = evaluate(model, test_loader)  # 在从未见过的测试集上做最终评估
print(f"\n===== 最终报告 =====")
print(f"最佳验证准确率: {best_val_acc:.2%}")
print(f"测试集准确率:   {test_acc:.2%}")
```

### 第 1 部分：构造数据并三路划分

```python
n = 600  # 600 个样本
X = torch.randn(n, 4)  # 4 个特征
y = ((X[:, 0] * 2 - X[:, 1] + X[:, 2]) > 0).long()  # 由特征线性组合决定的二分类标签
```

- `n = 600` —— 设定样本总数为 600 条，后面划分时会按 400/100/100 分配。
- `X = torch.randn(n, 4)` —— 生成一个形状为 `(600, 4)` 的特征矩阵：`randn` 产生标准正态分布（均值 0、标准差 1）的随机数，600 行代表 600 个样本，4 列代表每个样本有 4 个特征。
- `y = ((X[:, 0] * 2 - X[:, 1] + X[:, 2]) > 0).long()` —— 这一行人为规定标签的生成规则，分四步看：① `X[:, 0]` 取所有样本的第 0 个特征，`X[:, 1]`、`X[:, 2]` 同理；② 计算线性组合 `第0特征×2 − 第1特征 + 第2特征`，得到一个长度为 600 的分数；③ `> 0` 把分数变成布尔值（True/False），即"分数为正归为 1 类，否则归为 0 类"；④ `.long()` 把 True/False 转成整数 1/0，因为交叉熵损失要求标签是整型。这样得到的 `y` 形状是 `(600,)`，每个元素是 0 或 1。注意第 3 个特征（下标 3）没参与标签计算，相当于一个"干扰特征"，模型需要自己学会忽略它。

```python
dataset = TensorDataset(X, y)  # 打包成数据集
train_set, val_set, test_set = random_split(dataset, [400, 100, 100])  # 按 400/100/100 随机切分
```

- `dataset = TensorDataset(X, y)` —— 把特征 `X` 和标签 `y` 按位置一一配对捆成一个数据集。捆好之后，取 `dataset[i]` 就能同时拿到第 i 个样本的特征和标签，保证两者永远不会错位。
- `train_set, val_set, test_set = random_split(dataset, [400, 100, 100])` —— 把 600 个样本**随机**切成三份：400 条训练、100 条验证、100 条测试，三个返回值按顺序解包给三个变量。`random_split` 内部洗牌的随机性受第 10 行的种子控制，所以每次切出来的三份完全相同。注意三个数字之和必须等于样本总数 600，否则会报错。

```python
train_loader = DataLoader(train_set, batch_size=32, shuffle=True)  # 训练加载器：打乱
val_loader = DataLoader(val_set, batch_size=32)  # 验证加载器
test_loader = DataLoader(test_set, batch_size=32)  # 测试加载器
```

- `train_loader = DataLoader(train_set, batch_size=32, shuffle=True)` —— 给训练集套上"分批取货机"：每次取 32 条（一个 batch），`shuffle=True` 表示每一轮开始前把 400 条样本重新洗乱。训练时打乱非常重要：如果不打乱，模型每轮都按相同顺序看数据，容易记住顺序、学到假象。400 ÷ 32 = 12 余 16，所以每轮有 13 个批次，最后一批 16 条。
- `val_loader = DataLoader(val_set, batch_size=32)` —— 验证集加载器。没有写 `shuffle`，默认不打乱——评估只是"对答案"，顺序无所谓，不打乱反而保证每次评估结果可比较。
- `test_loader = DataLoader(test_set, batch_size=32)` —— 测试集加载器，同理不打乱。批次大小不影响准确率的计算结果，只影响分几次算完。

### 第 2 部分：定义模型

```python
class Classifier(nn.Module):  # 定义分类网络
    def __init__(self):  # 构造函数
        super().__init__()  # 调用父类构造
        self.net = nn.Sequential(  # Sequential 把多层按顺序串成一个整体
            nn.Linear(4, 32),  # 输入层 4 -> 隐藏层 32
            nn.ReLU(),  # 非线性激活
            nn.Linear(32, 16),  # 隐藏层 32 -> 16
            nn.ReLU(),  # 非线性激活
            nn.Linear(16, 2),  # 输出层 16 -> 2 个类别
        )
```

- `class Classifier(nn.Module)` —— 定义一个名叫 `Classifier`（分类器）的新类，括号里的 `nn.Module` 表示继承 PyTorch 的模型基类。所有自定义网络都必须继承它，才能自动获得参数管理、模式切换（train/eval）、保存加载等能力。
- `def __init__(self)` —— 构造函数，创建模型对象时自动执行，负责搭建网络结构。
- `super().__init__()` —— 调用父类 `nn.Module` 的构造函数。这是**硬性规定**：不写这行，父类的内部登记机制不会启动，后面保存参数、切换模式等操作都会报错。
- `self.net = nn.Sequential(...)` —— `nn.Sequential` 是一个"流水线容器"，括号里的各层会按书写顺序依次执行，前一层的输出自动成为后一层的输入。把它挂在 `self.net` 名下，它内部所有层的参数都会被自动登记进模型。
- `nn.Linear(4, 32)` —— 全连接层（线性层）：输入 4 维、输出 32 维，数学上就是 `输出 = x·W + b`。它有 `32×4` 个权重和 `32` 个偏置共 160 个可学习参数。4 必须等于特征数。
- `nn.ReLU()` —— ReLU 激活函数：负数归零、正数原样通过。它没有参数，作用是给网络注入非线性——没有它，三层线性层叠起来数学上等价于一层，网络再深也只会画直线。
- `nn.Linear(32, 16)` —— 第二个全连接层，把 32 维压缩到 16 维。注意它的输入维度 32 必须等于上一层的输出维度，这是 Sequential 串联时的铁律。
- `nn.ReLU()` —— 再来一次非线性激活。
- `nn.Linear(16, 2)` —— 输出层：16 维进、2 维出。2 对应二分类的两个类别，输出的两个数叫 logits（原始得分），谁大预测谁。后面接的是 `CrossEntropyLoss`，它内部自带 Softmax，所以**这里不要加 Softmax**，否则等于算了两次，训练会变差。

```python
    def forward(self, x):  # 前向传播
        return self.net(x)  # 数据依次流过 Sequential 中各层
```

- `def forward(self, x)` —— 定义前向传播方法，`x` 是输入张量（形状 `(batch大小, 4)`）。PyTorch 约定：你写 `model(bx)` 时，框架会自动调用这个 `forward` 方法。
- `return self.net(x)` —— 把输入交给刚才搭好的流水线，数据依次经过 Linear→ReLU→Linear→ReLU→Linear，返回形状为 `(batch大小, 2)` 的得分。

### 实例化模型、损失函数、优化器

```python
model = Classifier()  # 实例化模型
criterion = nn.CrossEntropyLoss()  # 交叉熵损失
optimizer = torch.optim.Adam(model.parameters(), lr=0.01)  # Adam 优化器（比 SGD 更常用）
```

- `model = Classifier()` —— 创建模型对象。这一步会执行 `__init__`，各层参数被随机初始化（初始化的随机性同样受种子控制）。
- `criterion = nn.CrossEntropyLoss()` —— 创建交叉熵损失函数，变量名 `criterion`（标准）是惯例。它的输入是"模型输出的原始得分 + 正确标签（整数）"，输出一个标量损失值，越小说明预测越准。
- `optimizer = torch.optim.Adam(model.parameters(), lr=0.01)` —— 创建 Adam 优化器。`model.parameters()` 把模型里所有可学习参数"交"给优化器管理；`lr=0.01` 是学习率，即每次参数更新的步子大小。步子太大容易来回震荡错过最优点，太小则学得慢，0.01 对 Adam 来说是一个偏快但常用的大小，本章问题简单所以能 hold 住。

### 第 3 部分：评估函数

```python
def evaluate(model, loader):  # 定义通用评估函数
    model.eval()  # 切换到评估模式（关闭 Dropout/BN 的训练行为）
    correct, total = 0, 0  # 计数器：预测正确数、总样本数
```

- `def evaluate(model, loader)` —— 定义一个通用评估函数：给它任意模型和任意数据加载器，它返回准确率。写成函数是因为验证集和测试集要各评估一次，同一套逻辑复用两遍，避免抄两份代码。
- `model.eval()` —— 把模型切到评估模式。对本章这个纯 Linear+ReLU 的网络其实没有实际影响，但如果网络里有 Dropout 或 BatchNorm，忘了切 eval 会让评估结果偏低且不稳定——所以把它当成铁律来记。
- `correct, total = 0, 0` —— 一行初始化两个计数器：`correct` 累计预测对的条数，`total` 累计评估过的总条数。

```python
    with torch.no_grad():  # 评估不需要梯度
        for bx, by in loader:  # 逐批次评估
            pred = model(bx).argmax(dim=1)  # 取得分最高的类别作为预测结果
            correct += (pred == by).sum().item()  # 累加预测正确的数量
            total += len(by)  # 累加样本总数
    return correct / total  # 返回准确率
```

- `with torch.no_grad():` —— 进入"不记录梯度"的上下文。评估只做前向计算，不需要反向传播，关掉梯度记录后 PyTorch 不构建计算图，内存更省、速度更快。注意它只作用于缩进在 `with` 块内的代码。
- `for bx, by in loader:` —— 逐批次遍历加载器。每次循环 `bx` 是形状 `(本批条数, 4)` 的特征、`by` 是形状 `(本批条数,)` 的标签。
- `pred = model(bx).argmax(dim=1)` —— 两步合一：`model(bx)` 前向得到 `(本批条数, 2)` 的得分；`.argmax(dim=1)` 沿第 1 维（类别维）找最大得分的下标，即每个样本的预测类别，结果是形状 `(本批条数,)` 的 0/1 张量。`dim=1` 不能写错：写成 `dim=0` 就变成"沿样本维比较"，结果完全不是想要的。
- `correct += (pred == by).sum().item()` —— 三步统计本批答对几条：`(pred == by)` 逐元素比较得到 True/False 张量；`.sum()` 把 True 当 1、False 当 0 求和，得到本批答对数（仍是一个 0 维张量）；`.item()` 把这个 0 维张量取出变成普通 Python 数字，再加进 `correct`。
- `total += len(by)` —— `len(by)` 是本批的样本条数（最后一批可能不足 32，用 `len` 最保险），累加进总数。
- `return correct / total` —— 用"答对数 ÷ 总数"得到准确率，是 0 到 1 之间的小数。注意这一行**没有缩进在 `with` 块里**，它在所有批次遍历完之后才执行一次。

### 第 4 部分：训练 + 每轮验证

```python
best_val_acc = 0.0  # 记录历史最佳验证准确率
for epoch in range(30):  # 训练 30 轮
    model.train()  # 切换到训练模式（与 eval 对应）
```

- `best_val_acc = 0.0` —— 初始化"历史最佳验证准确率"为 0。它扮演"纪录保持者"的角色：之后每一轮的验证成绩只要超过它，就刷新纪录并把模型存档。
- `for epoch in range(30)` —— 最外层循环：把整个训练集完整学习 30 遍（30 个 epoch）。`epoch` 从 0 数到 29。
- `model.train()` —— 每轮开头切回训练模式。之所以要"每轮都切"，是因为上一轮结尾的 `evaluate` 把模型切到了 eval 模式；不切换回来的话，含 Dropout/BN 的网络会一直处于考试状态，训练效果大打折扣。

```python
    for bx, by in train_loader:  # 训练循环五步曲
        loss = criterion(model(bx), by)  # 前向 + 算损失
        optimizer.zero_grad()  # 清梯度
        loss.backward()  # 反向传播
        optimizer.step()  # 更新参数
```

- `for bx, by in train_loader:` —— 内层循环：逐批次取训练数据。因为建加载器时设了 `shuffle=True`，每一轮拿到的批次顺序都不同。
- `loss = criterion(model(bx), by)` —— 一行干两件事：`model(bx)` 前向算出 `(32, 2)` 的得分，`criterion(...)` 拿得分和真实标签 `by` 算出本批的交叉熵损失（一个标量）。这是"对答案找差距"的一步。
- `optimizer.zero_grad()` —— 把上一次迭代算出的梯度全部清零。PyTorch 的梯度默认是**累加**的（设计初衷是支持梯度累积技巧），如果忘了清零，梯度会越积越多，参数更新方向完全错乱，这是新手最常踩的坑之一。
- `loss.backward()` —— 反向传播：从损失出发，沿计算图自动求出每个参数的梯度，存进各参数的 `.grad` 属性。这一步只做"计算"，还不改参数。
- `optimizer.step()` —— 优化器根据各参数的 `.grad`，按 Adam 的规则真正更新参数数值。至此一次参数更新完成。
- 整体记忆口诀：**前向算损失 → 清梯度 → 反向 → 更新**。清梯度必须在 backward 之前，更新必须在 backward 之后。

```python
    val_acc = evaluate(model, val_loader)  # 在验证集上评估
    if val_acc > best_val_acc:  # 如果验证准确率创新高
        best_val_acc = val_acc  # 更新最佳记录
        torch.save(model.state_dict(), "best_model.pt")  # 保存当前最优模型的参数
```

- `val_acc = evaluate(model, val_loader)` —— 一轮训练结束后，立刻调用前面定义的评估函数，在验证集上考一次"模拟考"，得到本轮的验证准确率。注意 `evaluate` 内部会把模型切到 eval 模式。
- `if val_acc > best_val_acc:` —— 判断本轮成绩是否刷新了历史纪录。这是"只保存最好版本"策略的闸门。
- `best_val_acc = val_acc` —— 刷新纪录值。
- `torch.save(model.state_dict(), "best_model.pt")` —— 把当前模型的所有参数（state_dict）写入当前目录下的 `best_model.pt` 文件。因为用的是覆盖写，训练全程磁盘上只保留"截至目前的巅峰版本"，不会越存越多。这就是为什么训练结束时得到的模型不一定是最后一轮的，而是**验证表现最好那一轮**的。

```python
    if (epoch + 1) % 10 == 0:  # 每 10 轮打印
        print(f"第 {epoch+1:2d} 轮 | 验证准确率={val_acc:.2%} | 历史最佳={best_val_acc:.2%}")
```

- `if (epoch + 1) % 10 == 0:` —— 每 10 轮打印一次日志。`epoch` 从 0 开始，所以用 `epoch + 1` 才是人类习惯的"第几轮"；`% 10 == 0` 表示轮数是 10 的倍数时（第 10、20、30 轮）才打印，避免 30 行日志刷屏。
- `print(f"第 {epoch+1:2d} 轮 | 验证准确率={val_acc:.2%} | 历史最佳={best_val_acc:.2%}")` —— f-string 格式化输出：`{epoch+1:2d}` 把轮次按整数输出、宽度占 2 格右对齐（个位数轮次前面补空格，多行日志能对齐）；`{val_acc:.2%}` 把小数按百分比格式显示并保留两位小数，比如 0.97 显示为 `97.00%`。一行同时给出"本轮成绩"和"历史最佳"，方便观察训练是否还在进步。

### 第 5 部分：加载最佳模型并出最终报告

```python
model.load_state_dict(torch.load("best_model.pt"))  # 把保存的最优参数载入模型
test_acc = evaluate(model, test_loader)  # 在从未见过的测试集上做最终评估
```

- `model.load_state_dict(torch.load("best_model.pt"))` —— 从里往外读：`torch.load` 把磁盘上的参数文件读回内存，`model.load_state_dict` 把这些参数灌进当前模型对象。执行完这行，`model` 就从"第 30 轮结束时的状态"回滚到了"验证准确率 99% 那一轮的状态"。这一步的意义：训练后期模型可能在训练集上越学越"钻牛角尖"，最后一轮的状态未必最靠谱，巅峰存档才是要交付的模型。
- `test_acc = evaluate(model, test_loader)` —— 让这份巅峰模型在**从未参与训练、也从未参与选模型**的测试集上考一次，得到唯一一次、也是最可信的最终成绩。

```python
print(f"\n===== 最终报告 =====")
print(f"最佳验证准确率: {best_val_acc:.2%}")
print(f"测试集准确率:   {test_acc:.2%}")
```

- `print(f"\n===== 最终报告 =====")` —— 打印报告标题。`\n` 是换行符，先空一行让报告和上面的训练日志在视觉上分开。
- `print(f"最佳验证准确率: {best_val_acc:.2%}")` —— 打印训练全程刷出的最高验证准确率，代表"挑模型时看到的成绩"。
- `print(f"测试集准确率:   {test_acc:.2%}")` —— 打印最终测试成绩。冒号后故意多打了两个空格，让两个百分数上下对齐，报告更整齐。这两个数字一摆，"训练—验证—测试—报告"的完整闭环就齐了。

## 运行结果与解读

本程序的真实运行输出如下：

```text
第 10 轮 | 验证准确率=97.00% | 历史最佳=99.00%
第 20 轮 | 验证准确率=95.00% | 历史最佳=99.00%
第 30 轮 | 验证准确率=98.00% | 历史最佳=99.00%

===== 最终报告 =====
最佳验证准确率: 99.00%
测试集准确率:   96.00%
```

逐项解读：

- **第 10 轮：验证准确率=97.00%，历史最佳=99.00%** —— 注意一个细节：第 10 轮的本轮成绩是 97%，但历史最佳已经是 99% 了。这说明在第 10 轮之前的某一轮（第 1~9 轮之间），验证准确率就已经冲到过 99%，并且那一刻的模型参数已经被写进了 `best_model.pt`。训练早期模型进步非常快。
- **第 20 轮：验证准确率=95.00%** —— 成绩从 97% 回落到 95%，这是**完全正常**的现象。训练数据的线性规则中混着干扰特征，且每轮批次顺序都不同，模型状态在"接近最优"的区域附近小幅波动。历史最佳仍定格在 99%，没有刷新，`best_model.pt` 也维持不变。
- **第 30 轮：验证准确率=98.00%** —— 又小幅回升，但仍未超过 99%。纵观三行日志：97% → 95% → 98%，在一个高水平上小幅震荡，说明模型早已收敛，继续增加轮数意义不大——这正是"精度与效率平衡"的直观体现。
- **最佳验证准确率： 99.00%** —— 全程的最高模拟考成绩，对应的模型已被保存。
- **测试集准确率： 96.00%** —— 巅峰模型在高考中拿到 96%。它比最佳验证准确率低 3 个百分点，这是正常且健康的：验证集参与了"选模型"的决策，99% 是"挑出来的最高分"，天然偏乐观；测试集完全中立，96% 才是模型真实水平的估计。两个数字差距不大（只有 3%），说明模型没有明显过拟合，泛化能力良好。如果测试成绩暴跌（比如只有 70%），那就要回头检查是否过拟合或数据划分出了问题。

看到以上输出，说明你学对了：日志每 10 轮一行、历史最佳只涨不跌、最终报告里测试成绩略低于最佳验证成绩，都是这套标准流程的典型表现。

## 小结

- 数据要分三份：**训练集**用来学、**验证集**用来选模型、**测试集**只在最后考一次；`random_split(dataset, [400, 100, 100])` 一行完成随机三路划分。
- 训练循环的内层是固定五步曲：`criterion` 算损失 → `zero_grad` 清梯度 → `backward` 反向传播 → `step` 更新参数，顺序不能乱，梯度清零最容易被忘。
- 评估前先 `model.eval()` 并用 `with torch.no_grad():` 包住；训练前切回 `model.train()`。`argmax(dim=1)` 把模型输出变成预测类别。
- 每轮结束在验证集上打分，**只有刷新历史最佳才 `torch.save` 存档**，训练完用 `load_state_dict` 恢复巅峰版本再测测试集——这是"用最少代价换最好精度"的标准做法。
- 测试准确率略低于最佳验证准确率是正常现象；两者差距过大才需要警惕过拟合。

## 动手练习

1. **调学习率**：把 `lr=0.01` 改成 `0.1`，再运行一次，观察验证准确率是否出现更剧烈的波动（甚至学不动）；再改成 `0.0001`，观察 30 轮内历史最佳能到多少。体会学习率"太大震荡、太小学不动"的含义。
2. **改变数据划分**：把 `random_split(dataset, [400, 100, 100])` 改成 `[300, 150, 150]`（注意三个数之和必须等于 600），观察测试准确率的变化，思考训练数据变少对最终成绩的影响。
3. **验证"巅峰存档"的价值**：把第 72 行 `model.load_state_dict(...)` 整行注释掉，直接用第 30 轮结束时的模型测测试集，对比两次的测试准确率，说说看为什么加载最佳模型通常更稳。
