## 核心概念讲解

**端到端项目流程。** 一个真实的 AI 训练项目绝不是"拿到数据就训练"。标准流程是：先检查数据质量（有没有缺失、异常），再做预处理（标准化），然后把数据切成训练集 / 验证集 / 测试集三份，接着建模、训练，最后在从未参与训练的测试集上做评估并写报告。本章代码严格按这个顺序分成了六个步骤。

**脏数据。** 真实采集的数据几乎总是"脏"的：传感器掉线会产生缺失值（NaN，Not a Number），传感器故障会产生离谱的异常值（比如正常范围 ±3 的数据里冒出一个 500）。哪怕只有一行脏数据混进去，也会污染均值和标准差的计算，进而毁掉整个标准化。所以清洗必须放在标准化之前。

**Z-score 标准化。** 把每个特征（每一列）减去该列的均值、再除以该列的标准差：

```
x' = (x - mean) / std
```

标准化后每列均值约为 0、标准差约为 1，各特征处于同一量级，模型训练更稳定、收敛更快。

**训练集 / 验证集 / 测试集。** 三者分工不同：训练集用来更新参数；验证集用来"监考"训练过程（挑最佳模型、决定何时早停）；测试集只在最后用一次，模拟模型上线后面对全新数据的表现。用验证集选模型、用测试集做终评，可以有效防止"模型背下了考题"（过拟合）。

**正则化组合拳。** 本章模型同时使用三种手段防止过拟合：BatchNorm（批归一化，把每层输入拉回到稳定分布）、Dropout（训练时随机丢弃 30% 神经元，迫使网络不依赖个别神经元）、早停（验证准确率连续多轮不提升就提前结束训练）。

**学习率衰减。** 训练初期用较大的学习率快速下降，后期把学习率减半、小碎步微调，避免在最优点附近来回震荡。本章用 `StepLR` 实现"每 10 轮把学习率乘以 0.5"。

**精确率与召回率。** 准确率在类别不均衡时会骗人。对故障检测而言，必须拆开看：

```
精确率 precision = TP / (TP + FP)   # 报出的故障里，有多少是真的（不误报）
召回率 recall    = TP / (TP + FN)   # 真实发生的故障里，抓到了多少（不漏报）
```

其中 TP（真正例）= 预测故障且确实故障；FP（假正例）= 误报；FN（假负例）= 漏报。设备故障场景中漏报可能酿成事故，所以召回率往往比精确率更重要。

## 完整代码

```python
"""
第 10 章：综合实战 —— 端到端智能训练项目
对应赛项知识点：对复杂的智能系统进行测试和训练并编写报告；
数据清洗 → 标准化 → 训练 → 调优 → 评估报告 全流程
任务：根据 8 个传感器特征预测设备是否故障（二分类）
"""
import torch  # 导入 PyTorch
import torch.nn as nn  # 神经网络模块
from torch.utils.data import DataLoader, TensorDataset, random_split  # 数据工具

torch.manual_seed(42)  # 固定随机种子

# ========== 步骤 1：构造并清洗数据（数据工程） ==========
n = 1200  # 1200 条设备记录
X = torch.randn(n, 8)  # 8 个传感器特征
# 故障与特征的非线性关系（真实业务中的规律往往是隐藏的）
y = ((X[:, 0] ** 2 + X[:, 1] * X[:, 2] - X[:, 3]) > 0.5).long()  # 0=正常, 1=故障

X[0] = float("nan")  # 制造脏数据：缺失值
X[10] = 500.0  # 制造脏数据：异常值

mask = ~torch.isnan(X).any(dim=1)  # 找出含 NaN 的行
mask &= (X.abs().max(dim=1).values < 100)  # 找出含异常值的行
X, y = X[mask], y[mask]  # 剔除脏数据
print(f"步骤 1 数据清洗：剩余 {len(X)} 条有效记录")

# ========== 步骤 2：标准化 ==========
mean, std = X.mean(dim=0), X.std(dim=0)  # 计算各特征的均值和标准差
X = (X - mean) / std  # Z-score 标准化
print("步骤 2 标准化完成：各特征均值≈0，标准差≈1")

# ========== 步骤 3：划分数据集 ==========
dataset = TensorDataset(X, y)  # 打包
train_set, val_set, test_set = random_split(dataset, [800, 200, len(X) - 1000])  # 训练/验证/测试
train_loader = DataLoader(train_set, batch_size=32, shuffle=True)  # 训练加载器
val_loader = DataLoader(val_set, batch_size=64)  # 验证加载器
test_loader = DataLoader(test_set, batch_size=64)  # 测试加载器
print(f"步骤 3 数据集划分：训练 {len(train_set)} / 验证 {len(val_set)} / 测试 {len(test_set)}")

# ========== 步骤 4：构建模型 ==========
model = nn.Sequential(  # 带正则化的 MLP
    nn.Linear(8, 64),  # 输入 8 -> 64
    nn.BatchNorm1d(64),  # 批归一化
    nn.ReLU(),  # 激活
    nn.Dropout(0.3),  # Dropout 防过拟合
    nn.Linear(64, 32),  # 64 -> 32
    nn.BatchNorm1d(32),  # 批归一化
    nn.ReLU(),  # 激活
    nn.Linear(32, 2),  # 输出 2 类
)
criterion = nn.CrossEntropyLoss()  # 交叉熵损失
optimizer = torch.optim.Adam(model.parameters(), lr=0.01)  # Adam 优化器
scheduler = torch.optim.lr_scheduler.StepLR(optimizer, step_size=10, gamma=0.5)  # 学习率衰减

# ========== 步骤 5：训练 + 早停 + 保存最佳模型 ==========
def evaluate(loader):  # 评估函数
    model.eval()  # 评估模式
    correct, total = 0, 0  # 计数器
    with torch.no_grad():  # 关闭梯度
        for bx, by in loader:  # 逐批次
            correct += (model(bx).argmax(1) == by).sum().item()  # 累计正确数
            total += len(by)  # 累计总数
    return correct / total  # 返回准确率

best_val, wait, patience = 0.0, 0, 8  # 早停相关变量：最佳验证准确率、等待计数、容忍轮数
print("步骤 5 开始训练：")
for epoch in range(60):  # 最多 60 轮
    model.train()  # 训练模式
    for bx, by in train_loader:  # 训练五步曲
        loss = criterion(model(bx), by)  # 前向 + 损失
        optimizer.zero_grad()  # 清梯度
        loss.backward()  # 反向传播
        optimizer.step()  # 更新参数
    scheduler.step()  # 每轮更新学习率

    val_acc = evaluate(val_loader)  # 验证集评估
    if val_acc > best_val:  # 验证准确率提升
        best_val, wait = val_acc, 0  # 更新记录
        torch.save(model.state_dict(), "device_best.pt")  # 保存最佳模型
    else:  # 未提升
        wait += 1  # 等待计数 +1
        if wait >= patience:  # 连续 8 轮无提升
            print(f"  第 {epoch+1} 轮触发早停")
            break  # 提前停止
    if (epoch + 1) % 10 == 0:  # 定期打印
        print(f"  第 {epoch+1:2d} 轮 | 验证准确率={val_acc:.2%} | 当前学习率={scheduler.get_last_lr()[0]:.4f}")

# ========== 步骤 6：测试并编写评估报告 ==========
model.load_state_dict(torch.load("device_best.pt"))  # 加载最佳模型
test_acc = evaluate(test_loader)  # 测试集准确率

# 计算精确率和召回率（故障检测中，漏报比误报更危险，所以召回率很重要）
model.eval()  # 评估模式
all_pred, all_true = [], []  # 收集所有预测和真实标签
with torch.no_grad():  # 关闭梯度
    for bx, by in test_loader:  # 逐批次
        all_pred.append(model(bx).argmax(1))  # 保存预测
        all_true.append(by)  # 保存真实
pred, true = torch.cat(all_pred), torch.cat(all_true)  # 拼接成完整张量

tp = ((pred == 1) & (true == 1)).sum().item()  # 真正例：预测故障且确实故障
fp = ((pred == 1) & (true == 0)).sum().item()  # 假正例：误报
fn = ((pred == 0) & (true == 1)).sum().item()  # 假负例：漏报
precision = tp / (tp + fp)  # 精确率 = TP/(TP+FP)：报的故障里有多少是真的
recall = tp / (tp + fn)  # 召回率 = TP/(TP+FN)：真实故障里抓到了多少

print("\n========== 评估报告 ==========")
print(f"最佳验证准确率 : {best_val:.2%}")
print(f"测试集准确率   : {test_acc:.2%}")
print(f"精确率         : {precision:.2%}")
print(f"召回率         : {recall:.2%}")
print("==============================")
```

### 步骤 1：构造并清洗数据

```python
n = 1200  # 1200 条设备记录
X = torch.randn(n, 8)  # 8 个传感器特征
```

- `n = 1200` —— 样本数量，即模拟 1200 条设备运行记录。
- `X = torch.randn(n, 8)` —— 生成形状为 `(1200, 8)` 的张量，每个数服从标准正态分布（均值 0、标准差 1）。可以理解为每台设备有 8 个传感器读数（温度、振动、电流……），所以 X 的每一行是一台设备，每一列是一个传感器特征。

```python
y = ((X[:, 0] ** 2 + X[:, 1] * X[:, 2] - X[:, 3]) > 0.5).long()  # 0=正常, 1=故障
```

- 这一行人为设定"故障规律"，分四步看：`X[:, 0]` 取所有行的第 0 列（形状 `(1200,)`），`** 2` 逐元素平方；`X[:, 1] * X[:, 2]` 是第 1 列与第 2 列逐元素相乘；再加上减去 `X[:, 3]`，得到一个 `(1200,)` 的分数。
- `... > 0.5` —— 逐元素比较，得到布尔张量（`True` 表示分数超过阈值，判为故障）。注意规律里有平方和乘积项，是**非线性**关系——这正是要用带激活函数的深层网络、而不是一层线性模型的原因。
- `.long()` —— 把布尔张量转成 64 位整数（`True→1`，`False→0`）。`CrossEntropyLoss` 要求标签必须是 `long` 类型，形状 `(1200,)`，0 表示正常、1 表示故障。

```python
X[0] = float("nan")  # 制造脏数据：缺失值
X[10] = 500.0  # 制造脏数据：异常值
```

- `X[0] = float("nan")` —— 把第 0 行整行（8 个特征）赋值为 NaN（Not a Number，非数），模拟传感器整路掉线产生的缺失数据。`X[0]` 是行索引，赋一个标量会广播到整行。
- `X[10] = 500.0` —— 把第 10 行整行赋值为 500.0。正常数据都在 ±3 左右波动，500 显然是传感器故障导致的异常值。这两行是故意埋下的"地雷"，用来演示清洗流程。

```python
mask = ~torch.isnan(X).any(dim=1)  # 找出含 NaN 的行
```

- `torch.isnan(X)` —— 逐元素判断是否为 NaN，返回同形状 `(1200, 8)` 的布尔张量。
- `.any(dim=1)` —— 沿第 1 维（列方向，即每行内部）做"或"归约：某一行只要有一个 NaN，该行为 `True`。结果形状 `(1200,)`。
- `~` —— 按位取反，对布尔张量就是"非"。所以整个表达式的含义是：`mask[i]` 为 `True` 表示第 i 行**不含** NaN，是干净行。

```python
mask &= (X.abs().max(dim=1).values < 100)  # 找出含异常值的行
```

- `X.abs()` —— 逐元素取绝对值（负的异常值如 -500 也能被捕获），形状不变。
- `.max(dim=1)` —— 沿每行求最大值，返回一个命名元组，`.values` 是最大值本身（形状 `(1200,)`），`.indices` 是最大值所在的列号（这里不需要）。
- `.values < 100` —— 逐元素比较：该行绝对值最大的元素都小于 100，才算"无异常"，得到 `(1200,)` 布尔张量。
- `mask &= ...` —— 等价于 `mask = mask & (...)`，把两个条件做逐元素"逻辑与"：既不含 NaN、又无异常值的行才保留为 `True`。`&` 是张量的逐元素与，不要写成 Python 的 `and`（`and` 不能对张量逐元素运算，会报错）。

```python
X, y = X[mask], y[mask]  # 剔除脏数据
print(f"步骤 1 数据清洗：剩余 {len(X)} 条有效记录")
```

- `X[mask]` —— 布尔掩码索引：只保留 `mask` 为 `True` 的行。我们埋了 2 行脏数据（第 0 行和第 10 行），所以 X 从 `(1200, 8)` 变成 `(1198, 8)`。
- `y[mask]` —— 标签必须用**同一个掩码**同步过滤，保持 X 的第 i 行和 y 的第 i 个元素一一对应。只过滤 X 不过滤 y 是新手常见错误，会导致特征和标签错位。
- `X, y = ...` —— 用元组解包同时重新赋值，一行完成两个张量的更新。
- `print(f"...{len(X)}...")` —— f-string 格式化字符串，`len(X)` 取张量第 0 维长度（行数），输出 1198，与运行结果一致。

### 步骤 2：标准化

```python
mean, std = X.mean(dim=0), X.std(dim=0)  # 计算各特征的均值和标准差
```

- `X.mean(dim=0)` —— 沿第 0 维（行方向）求均值，即对**每一列**（每个特征）求所有样本的平均，结果形状 `(8,)`。
- `X.std(dim=0)` —— 同理求每列的标准差，形状 `(8,)`。
- 用逗号同时赋值给 `mean` 和 `std`，是元组解包写法。注意这一步必须在清洗之后做——如果没先删掉那行 500.0，第 0 列（其实所有列，因为整行都是 500）的均值和标准差都会被严重带偏。

```python
X = (X - mean) / std  # Z-score 标准化
```

- `X - mean` —— 广播机制：X 形状 `(1198, 8)`，mean 形状 `(8,)`，mean 被自动"复制"成 1198 行后逐元素相减，等价于每个元素减去自己所在列的均值。
- `/ std` —— 同样广播，逐元素除以所在列的标准差。结果每列均值≈0、标准差≈1，8 个特征处于同一量级，没有哪个特征会因为数值大而主导梯度。

```python
print("步骤 2 标准化完成：各特征均值≈0，标准差≈1")
```

- 打印提示信息。这里只打印了文字说明，想验证的话可以自己加一句 `print(X.mean(dim=0), X.std(dim=0))`，会看到均值接近 0、标准差接近 1。

### 步骤 3：划分数据集

```python
dataset = TensorDataset(X, y)  # 打包
```

- `TensorDataset(X, y)` —— 把特征张量和标签张量打包成一个数据集对象。它要求两个张量第 0 维长度一致（都是 1198），之后 `dataset[i]` 会同时取出 `X[i]` 和 `y[i]`，保证取数时特征和标签永远配对。

```python
train_set, val_set, test_set = random_split(dataset, [800, 200, len(X) - 1000])  # 训练/验证/测试
```

- `random_split(dataset, [800, 200, len(X) - 1000])` —— 把数据集随机切成三份：训练集 800 条、验证集 200 条、测试集 `1198 - 1000 = 198` 条。三个长度之和必须等于数据集总长（1198），否则会报错。用 `len(X) - 1000` 而不是写死 198 的好处是：清洗掉多少条脏数据都不用改这行代码。
- 返回值按顺序解包给 `train_set, val_set, test_set`。因为前面固定了种子，每次运行切分结果相同。
- 三份数据的职责：训练集用于梯度更新；验证集用于训练过程中的"监考"（决定保存哪个模型、何时早停）；测试集全程不参与训练，留到最后做终评。

```python
train_loader = DataLoader(train_set, batch_size=32, shuffle=True)  # 训练加载器
val_loader = DataLoader(val_set, batch_size=64)  # 验证加载器
test_loader = DataLoader(test_set, batch_size=64)  # 测试加载器
```

- `DataLoader(train_set, batch_size=32, shuffle=True)` —— 训练加载器：每次迭代吐出 32 条样本组成一个 batch（批次）。`shuffle=True` 表示每一轮（epoch，即完整遍历一遍训练集）开始前把数据重新洗牌，避免模型记住样本顺序。800 条 / 32 = 25 个 batch。
- `val_loader` / `test_loader` —— 验证和测试只做前向推理、不更新参数，顺序无所谓，所以不打乱（`shuffle` 默认 `False`）；batch 可以开大些（64），让评估更快。注意这里 `shuffle=True` 只给训练集，给验证/测试打乱虽不影响准确率，但没有任何收益，是多余的。
- `len(train_set)` 等 —— Subset 对象支持 `len()`，打印出 800 / 200 / 198，三数之和正好 1198。

### 步骤 4：构建模型

```python
model = nn.Sequential(  # 带正则化的 MLP
    nn.Linear(8, 64),  # 输入 8 -> 64
    nn.BatchNorm1d(64),  # 批归一化
    nn.ReLU(),  # 激活
    nn.Dropout(0.3),  # Dropout 防过拟合
    nn.Linear(64, 32),  # 64 -> 32
    nn.BatchNorm1d(32),  # 批归一化
    nn.ReLU(),  # 激活
    nn.Linear(32, 2),  # 输出 2 类
)
```

- `nn.Sequential(...)` —— 顺序容器：括号里的层按书写顺序依次执行，前一层的输出自动作为后一层的输入。适合这种"一条直线走到底"的 MLP（多层感知机）。
- `nn.Linear(8, 64)` —— 全连接层（线性层），把 8 维输入映射到 64 维。数学上是 `y = Wx + b`，权重 W 形状 `(64, 8)`、偏置 b 形状 `(64,)`。输入张量形状从 `(batch, 8)` 变为 `(batch, 64)`。
- `nn.BatchNorm1d(64)` —— 批归一化层：把一个 batch 内 64 个通道各自的分布拉回到均值 0、方差 1 附近，再学一对缩放平移参数。作用是稳定每层输入分布、允许用更大的学习率、加快收敛，还带点正则效果。`1d` 表示处理一维特征向量（区别于图像用的 `BatchNorm2d`）。
- `nn.ReLU()` —— 激活函数，`f(x) = max(0, x)`，负数归零、正数直通。没有它，多个线性层叠起来仍等价于一个线性层，就学不会本任务中的平方、乘积这类非线性规律。
- `nn.Dropout(0.3)` —— 训练时以 30% 的概率随机把某些神经元的输出置零，迫使网络不依赖个别神经元，从而防止过拟合。注意：它只在 `model.train()` 模式下生效，`model.eval()` 模式下自动关闭。
- `nn.Linear(64, 32)` —— 第二个全连接层，64 维压缩到 32 维，`(batch, 64)` → `(batch, 32)`。
- `nn.BatchNorm1d(32)` 与 `nn.ReLU()` —— 第二层同样配套批归一化和激活。
- `nn.Linear(32, 2)` —— 输出层，把 32 维压到 2 维，对应"正常 / 故障"两个类别。输出形状 `(batch, 2)`，每个数是该类别的原始得分（logit，未归一化的打分），不需要手动加 Softmax——`CrossEntropyLoss` 内部自带。

```python
criterion = nn.CrossEntropyLoss()  # 交叉熵损失
```

- 定义损失函数（评判"预测有多差"的标准）。`CrossEntropyLoss` 是分类任务的标准损失，输入是模型输出的原始得分（形状 `(batch, 2)`）和整数标签（形状 `(batch,)`，值为 0 或 1）。它内部先对得分做 Softmax 变成概率，再取正确类别概率的负对数——预测越自信且正确，损失越小。

```python
optimizer = torch.optim.Adam(model.parameters(), lr=0.01)  # Adam 优化器
```

- `model.parameters()` —— 把模型中所有可学习参数（各 Linear 层的 W 和 b、BatchNorm 的缩放平移参数）收集起来交给优化器管理。
- `torch.optim.Adam(..., lr=0.01)` —— Adam 优化器：在梯度下降基础上，为每个参数自动维护自适应的步长，收敛快、对超参数不敏感，是工程上的默认首选。`lr=0.01` 是初始学习率（每次参数更新的步长系数），比 SGD 常用的 0.01 略大是 Adam 的常见起手值之一。

```python
scheduler = torch.optim.lr_scheduler.StepLR(optimizer, step_size=10, gamma=0.5)  # 学习率衰减
```

- 学习率调度器，挂在优化器上。`step_size=10, gamma=0.5` 的含义：每调用 10 次 `scheduler.step()`（即每训练 10 轮），把学习率乘以 0.5。于是第 1~10 轮 lr=0.01，第 11~20 轮 lr=0.005，第 21~30 轮 lr=0.0025……初期大踏步快速下降，后期小碎步精调，避免在最优点附近来回震荡。

### 步骤 5：训练 + 早停 + 保存最佳模型

```python
def evaluate(loader):  # 评估函数
    model.eval()  # 评估模式
    correct, total = 0, 0  # 计数器
    with torch.no_grad():  # 关闭梯度
        for bx, by in loader:  # 逐批次
            correct += (model(bx).argmax(1) == by).sum().item()  # 累计正确数
            total += len(by)  # 累计总数
    return correct / total  # 返回准确率
```

- `def evaluate(loader):` —— 定义通用的评估函数，参数 `loader` 可以是验证加载器也可以是测试加载器，写一次复用两次。
- `model.eval()` —— 切到评估模式。这一步至关重要：它会让 Dropout 停止随机丢弃、BatchNorm 改用训练时累计的全局统计量。忘了切会导致评估结果偏低且不稳定。
- `correct, total = 0, 0` —— 两个计数器：预测正确的样本数和总样本数。
- `with torch.no_grad():` —— 上下文管理器，块内所有运算不记录梯度。评估不需要反向传播，关掉梯度既省内存又提速。评估完退出块，梯度自动恢复。
- `for bx, by in loader:` —— 逐批次取数据，`bx` 是特征（形状 `(batch, 8)`），`by` 是对应标签（形状 `(batch,)`）。
- `model(bx)` —— 前向传播，输出 `(batch, 2)` 的得分。
- `.argmax(1)` —— 沿第 1 维（类别维）取最大得分的下标，即预测类别，形状 `(batch,)`。这里下标 0/1 正好对应类别 0/1。
- `(... == by)` —— 逐元素比较预测与真实标签，得到布尔张量；`.sum()` 统计其中 `True` 的个数（本批正确数）；`.item()` 把单元素张量取出成 Python 数字，才能累加到计数器上。
- `total += len(by)` —— 累加本批样本数。不能用固定 batch_size 乘次数，因为最后一个 batch 可能不满（比如 198 条数据、batch 64，最后一批只有 6 条）。
- `return correct / total` —— 返回准确率（0~1 之间的小数）。函数结束后，`model.eval()` 的状态会一直保留，所以训练循环每轮开头要重新 `model.train()`。

```python
best_val, wait, patience = 0.0, 0, 8  # 早停相关变量
```

- `best_val` —— 历史最佳验证准确率，初始 0.0，只要第一次评估就会刷新。
- `wait` —— "已经连续多少轮没有提升"的计数器。
- `patience` —— 容忍轮数上限 8：连续 8 轮验证准确率没超过历史最佳，就判定训练已饱和，提前停止（早停）。

```python
for epoch in range(60):  # 最多 60 轮
    model.train()  # 训练模式
```

- `for epoch in range(60)` —— 最多训练 60 个 epoch（一轮 = 完整遍历一遍训练集）。设上限是为了兜底；有了早停，实际往往跑不满 60 轮（本次运行第 24 轮就停了）。
- `model.train()` —— 每轮开头切回训练模式，开启 Dropout 和 BatchNorm 的批次统计。因为 `evaluate()` 里切过 `eval()`，这里必须切回来，顺序不能反。

```python
    for bx, by in train_loader:  # 训练五步曲
        loss = criterion(model(bx), by)  # 前向 + 损失
        optimizer.zero_grad()  # 清梯度
        loss.backward()  # 反向传播
        optimizer.step()  # 更新参数
```

- 内层循环逐批训练，这就是前面章节反复强调的"训练五步曲"：
- `model(bx)` —— 前向传播，得到 `(32, 2)` 的得分（最后一个 batch 可能不足 32）。
- `loss = criterion(..., by)` —— 计算本批的交叉熵损失，是一个标量张量。
- `optimizer.zero_grad()` —— 把上次迭代留在参数上的梯度清零。PyTorch 的梯度默认**累加**，不清零的话梯度会越滚越大，训练直接崩掉。这一步必须放在 `backward()` 之前。
- `loss.backward()` —— 反向传播：自动求导，算出损失对每个参数的梯度，存进各参数的 `.grad` 属性。
- `optimizer.step()` —— 优化器根据梯度真正更新参数（Adam 规则：自适应步长 × 梯度方向），模型就此"学"了一点。

```python
    scheduler.step()  # 每轮更新学习率
```

- 每完成一轮调用一次，调度器内部计数 +1；数到 10 的倍数时把优化器里的学习率乘以 0.5。注意它放在**内层 batch 循环之外**——按轮衰减，不是按 batch 衰减。

```python
    val_acc = evaluate(val_loader)  # 验证集评估
    if val_acc > best_val:  # 验证准确率提升
        best_val, wait = val_acc, 0  # 更新记录
        torch.save(model.state_dict(), "device_best.pt")  # 保存最佳模型
    else:  # 未提升
        wait += 1  # 等待计数 +1
        if wait >= patience:  # 连续 8 轮无提升
            print(f"  第 {epoch+1} 轮触发早停")
            break  # 提前停止
```

- `val_acc = evaluate(val_loader)` —— 每轮训练完，用验证集"监考"一次，得到 0~1 的准确率。
- `if val_acc > best_val:` —— 和历史最佳比较。这里用严格大于：只有确实更好才更新。
- `best_val, wait = val_acc, 0` —— 刷新最佳纪录，同时把等待计数清零（重新开始计时）。
- `torch.save(model.state_dict(), "device_best.pt")` —— 把当前模型的参数（`state_dict()` 返回一个"层名 → 参数张量"的字典）保存到磁盘文件 `device_best.pt`。只存参数不存结构，是 PyTorch 推荐的保存方式。这样即使后面继续训练把模型练"过拟合"了，磁盘上始终保留着验证表现最好的那一版。
- `else:` 分支（没有提升时）：`wait += 1` 累计一轮"没进步"。
- `if wait >= patience:` —— 连续 8 轮无提升，判定收敛。`print(f"  第 {epoch+1} 轮触发早停")` 打印提示（`epoch` 从 0 开始，所以 `+1` 才是人类习惯的第几轮），然后 `break` 跳出训练循环，避免无谓的算力浪费和过拟合。

```python
    if (epoch + 1) % 10 == 0:  # 定期打印
        print(f"  第 {epoch+1:2d} 轮 | 验证准确率={val_acc:.2%} | 当前学习率={scheduler.get_last_lr()[0]:.4f}")
```

- `(epoch + 1) % 10 == 0` —— 每 10 轮打印一次进度（第 10、20、30…轮），避免日志刷屏。
- `{epoch+1:2d}` —— 格式化为宽度 2 的整数，个位数前面补空格，让多行日志对齐美观。
- `{val_acc:.2%}` —— 把小数按百分比格式输出并保留两位小数，如 `0.895` 显示为 `89.50%`。
- `scheduler.get_last_lr()[0]` —— 获取调度器记录的当前学习率（返回一个列表，取第 0 个元素），`{...:.4f}` 保留 4 位小数。用它可以在日志里亲眼看到学习率从 0.01 衰减到 0.005、0.0025 的过程。

### 步骤 6：测试并编写评估报告

```python
model.load_state_dict(torch.load("device_best.pt"))  # 加载最佳模型
test_acc = evaluate(test_loader)  # 测试集准确率
```

- `torch.load("device_best.pt")` —— 从磁盘读回之前保存的最佳参数字典。
- `model.load_state_dict(...)` —— 把这份参数灌回模型。经过早停，内存里的模型已经又训练了若干轮（可能过拟合），加载后恢复到验证表现最好的那一刻的状态。
- `test_acc = evaluate(test_loader)` —— 用恢复后的最佳模型在**从未参与任何训练决策**的测试集上评估，得到最能代表"上线后真实表现"的准确率。复用步骤 5 写的 `evaluate`，无需重造轮子。

```python
model.eval()  # 评估模式
all_pred, all_true = [], []  # 收集所有预测和真实标签
with torch.no_grad():  # 关闭梯度
    for bx, by in test_loader:  # 逐批次
        all_pred.append(model(bx).argmax(1))  # 保存预测
        all_true.append(by)  # 保存真实
pred, true = torch.cat(all_pred), torch.cat(all_true)  # 拼接成完整张量
```

- 精确率和召回率需要拿到**每一个样本**的预测结果，光靠 `evaluate` 返回的总准确率不够，所以要再遍历一遍测试集，把所有预测和真实标签收集起来。
- `model.eval()` 与 `with torch.no_grad():` —— 与 `evaluate` 中同理：评估模式保证 Dropout 关闭、BatchNorm 用全局统计量；关闭梯度省内存提速。
- `all_pred.append(model(bx).argmax(1))` —— 每批得到 `(batch,)` 的预测类别，追加到列表。
- `all_true.append(by)` —— 对应的真实标签也追加到列表。两个列表平行增长，顺序一一对应。
- `torch.cat(all_pred)` —— 把列表里的若干个小张量沿第 0 维拼接成一个 `(198,)` 的完整张量。`torch.cat` 要求各张量除拼接维外形状一致，这里都是一维，直接拼接即可。

```python
tp = ((pred == 1) & (true == 1)).sum().item()  # 真正例：预测故障且确实故障
fp = ((pred == 1) & (true == 0)).sum().item()  # 假正例：误报
fn = ((pred == 0) & (true == 1)).sum().item()  # 假负例：漏报
```

- `pred == 1` 得到"预测为故障"的布尔张量，`true == 1` 得到"真实为故障"的布尔张量，`&` 逐元素逻辑与：两个都成立才是真正例 TP。`.sum()` 统计个数，`.item()` 取出成整数。
- `fp` —— 预测为故障（`pred == 1`）但实际正常（`true == 0`）：把好的设备误报成故障，会浪费检修人力。
- `fn` —— 预测为正常（`pred == 0`）但实际故障（`true == 1`）：漏报！设备带病运行，在工业场景中最危险。
- 注意这里的 `&` 同样不能写成 `and`。

```python
precision = tp / (tp + fp)  # 精确率 = TP/(TP+FP)
recall = tp / (tp + fn)  # 召回率 = TP/(TP+FN)
```

- `precision` —— 在所有"被判定为故障"的设备（TP+FP）中，真正故障的占比。精确率高 = 误报少 = 检修不白跑。
- `recall` —— 在所有"真实发生故障"的设备（TP+FN）中，被成功抓出来的占比。召回率高 = 漏报少 = 安全隐患少。
- 两者是天然矛盾体：阈值放宽则召回升、精确降。工业故障检测通常优先保召回率（宁可多查几台好设备，不能放过一台坏设备）。

```python
print("\n========== 评估报告 ==========")
print(f"最佳验证准确率 : {best_val:.2%}")
print(f"测试集准确率   : {test_acc:.2%}")
print(f"精确率         : {precision:.2%}")
print(f"召回率         : {recall:.2%}")
print("==============================")
```

- `"\n"` 开头先换一行，让报告和训练日志视觉上分开。
- 四个指标统一用 `:.2%` 格式化为百分比、保留两位小数；冒号后留了不同宽度的空格让数值列对齐——报告的可读性也是职业素养的一部分，赛项中"编写报告"本就是评分点。
- 为什么同时报四个数：最佳验证准确率反映调优过程的天花板；测试集准确率反映泛化能力；精确率、召回率则把二分类结果拆成"误报"和"漏报"两个维度，这在类别不均衡或代价不对称的场景下比单一准确率诚实得多。

- **"标准化完成"** —— 提示信息。此时 X 的每列均值≈0、标准差≈1，8 个传感器特征被拉到同一量级。
- **"训练 800 / 验证 200 / 测试 198"** —— 三个数加起来 1198，与清洗后的总量吻合，说明 `len(X) - 1000` 的动态写法正确兜底。约 2/3 训练、1/6 验证、1/6 测试，是常见配比。
- **第 10 轮：验证准确率 89.50%，学习率 0.0050** —— 前 10 轮用 lr=0.01 快速学习，第 10 轮结束时 `scheduler.step()` 被调用了 10 次，学习率恰好减半到 0.005。日志里学习率的这次跳变，证明 StepLR 生效了。
- **第 20 轮：验证准确率 92.50%，学习率 0.0025** —— 准确率继续爬升，学习率再次减半。小学习率让模型在最优点附近精细微调。
- **"第 24 轮触发早停"** —— 最佳纪录 93.50% 是在第 16 轮创下的，第 17~24 轮连续 8 轮没能超越，达到 `patience=8` 的上限，训练提前终止。原本最多跑 60 轮，早停省下了一多半时间，还避免了后段训练可能带来的过拟合。
- **最佳验证准确率 93.50% vs 测试集准确率 92.42%** —— 两者接近（差约 1 个百分点），说明模型没有明显过拟合，验证集上挑出的"最佳模型"在全新数据上同样站得住。若测试准确率远低于验证准确率，就要警惕过拟合或数据划分有问题。
- **精确率 89.26%** —— 模型报出的故障中约九成是真的，误报控制得不错。
- **召回率 98.18%** —— 真实故障中约 98% 被成功抓到，漏报极少。对设备故障检测这种"漏报代价远大于误报"的场景，这是最令人安心的指标。有兴趣的读者可以反推一下：98.18% ≈ 108/110，即测试集中约 110 台真实故障设备只漏掉了 2 台；89.26% ≈ 108/121，即 121 次故障报警里有 13 次是误报；测试集 198 条中 183 条预测正确（92.42%），数字完全自洽。

## 小结

- 完整项目六步走：数据清洗 → 标准化 → 数据集划分 → 建模 → 训练调优 → 评估报告，顺序不能乱，清洗必须在标准化之前。
- 用 `torch.isnan(X).any(dim=1)` 和 `X.abs().max(dim=1).values` 配合布尔掩码剔除脏数据，X 和 y 必须用同一个掩码同步过滤。
- BatchNorm + Dropout + 早停是防过拟合的常用组合拳；`StepLR` 让学习率"先大后小"，兼顾收敛速度与精度。
- 每轮训练遵循五步曲：前向 → 算损失 → 清梯度 → 反向传播 → 更新参数；评估时记得 `model.eval()` + `torch.no_grad()`。
- 报告不能只写准确率：精确率看误报、召回率看漏报；故障检测类任务优先保召回率。验证集挑模型、测试集做终评，两者接近才说明模型可靠。

## 动手练习

1. **观察脏数据的破坏力**：把清洗用的两行 `mask` 代码注释掉（即不剔除 NaN 和 500.0），直接标准化并训练。观察输出：标准化被异常值带偏、NaN 让损失变成 nan、准确率大幅下降。由此体会"清洗必须先于标准化"的原因，然后恢复代码。
2. **调整早停耐心值**：把 `patience = 8` 改成 `3`，重新运行，观察早停提前到哪一轮、最佳验证准确率和测试准确率如何变化；再改成 `20` 试试。体会"耐心太小容易欠拟合、太大容易过拟合且浪费时间"的权衡。
3. **改变类别判定的严格程度**：在步骤 6 收集预测时，把 `model(bx).argmax(1)` 改成 `(model(bx).softmax(1)[:, 1] > 0.3).long()`（故障概率超过 30% 就报警，比默认的 50% 更敏感）。重新计算精确率和召回率，观察召回率上升、精确率下降的现象，理解两者此消彼长的关系。
