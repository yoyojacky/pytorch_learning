## 核心概念讲解

### 什么是梯度（Gradient）

中学数学告诉我们：函数某一点的**导数**就是该点切线的斜率，斜率为正说明函数在该点随自变量增大而增大，斜率为负则相反。梯度的意思是"函数往哪个方向走上升得最快"，对于只有一个自变量的函数，梯度就是导数；对于有多个自变量的函数（比如损失同时取决于 `w` 和 `b`），梯度是每个自变量偏导数组成的向量。

梯度最重要的性质：**沿着梯度的反方向走，函数值下降得最快**。这就是"梯度下降"的全部原理。

### 什么是反向传播（backward）

神经网络训练时，我们先从输入算到输出、算出损失（这叫**前向传播**），再从损失往回倒推，算出损失对每一个参数的梯度（这叫**反向传播**）。手工推导梯度公式很容易出错，PyTorch 的 Autograd 引擎会默默记录每一个张量参与了哪些运算（组成一张"计算图"），只要调用一次 `loss.backward()`，就自动按链式法则把所有梯度算好。

### 什么是梯度下降

想让损失（loss）尽可能小，就反复做三件事：

1. 用当前参数做预测，算出损失；
2. 反向传播，算出损失对每个参数的梯度；
3. 把参数往梯度的反方向挪一小步：

```
w = w - learning_rate * w的梯度
b = b - learning_rate * b的梯度
```

其中 `learning_rate`（学习率）控制每一步迈多大：太小则训练慢，太大则可能"跨过"最低点、来回震荡甚至发散。

### 什么是均方误差（MSE）

"损失函数"用来衡量预测有多差。本章用的是**均方误差**（Mean Squared Error，MSE）：把每个样本的"预测值 − 真实值"平方后取平均。

```
MSE = ( 所有样本 (y_pred - y_true)² 的平均 )
```

平方有两个好处：一是让误差永远非负；二是误差越大惩罚越重，模型会更努力修正大错误。

### 本章的四个关键 API

- `requires_grad=True`：告诉 PyTorch "这个张量我要算梯度，请帮我记录它的运算"。
- `x.grad`：调用 `backward()` 之后，梯度就保存在这里。
- `torch.no_grad()`：进入这个上下文后，运算不再被记录到计算图里——更新参数时用，省内存也防止出错。
- `w.grad.zero_()`：把梯度清零。PyTorch 默认会把新梯度**累加**到旧梯度上，所以每轮更新完必须手动清零。

## 完整代码

```python
"""
第 2 章：自动求导（Autograd）—— 梯度下降的原理
对应赛项知识点：理解概率论、统计学及线性代数在模型中的实现路径；
学习率对训练稳定性的影响（本章首次接触学习率）
"""
import torch  # 导入 PyTorch

# ========== 1. 自动求导基础 ==========
x = torch.tensor(2.0, requires_grad=True)  # 创建一个需要追踪梯度的标量张量
y = x ** 2 + 3 * x + 1  # 定义函数 y = x² + 3x + 1，PyTorch 会自动记录计算图
y.backward()  # 反向传播：计算 y 对 x 的导数 dy/dx = 2x + 3
print("x = 2 时，dy/dx =", x.grad)  # x.grad 保存梯度 -> 2*2+3 = 7

# ========== 2. 用梯度下降拟合 y = 3x + 2（手写训练过程） ==========
torch.manual_seed(42)  # 固定随机种子，保证每次运行结果一致（可复现）

# 生成 100 个样本：y = 3x + 2 + 噪声
X = torch.rand(100, 1) * 10  # 100 个 0~10 之间的随机数作为输入，形状 (100,1)
y_true = 3 * X + 2 + torch.randn(100, 1)  # 真实标签 = 3x+2 加随机噪声

# 初始化待学习的参数 w 和 b
w = torch.randn(1, requires_grad=True)  # 权重，随机初始化，需要梯度
b = torch.zeros(1, requires_grad=True)  # 偏置，初始化为 0，需要梯度

learning_rate = 0.01  # 学习率：每次参数更新的步长（赛项考点：影响训练稳定性）

for epoch in range(200):  # 训练 200 轮（epoch = 遍历一遍全部数据）
    y_pred = w * X + b  # 前向传播：用当前参数做预测
    loss = ((y_pred - y_true) ** 2).mean()  # 均方误差损失 MSE
    loss.backward()  # 反向传播：自动计算 loss 对 w、b 的梯度

    with torch.no_grad():  # 参数更新不需要记录计算图，用 no_grad 关闭追踪
        w -= learning_rate * w.grad  # 梯度下降更新 w：w = w - lr * 梯度
        b -= learning_rate * b.grad  # 梯度下降更新 b

    w.grad.zero_()  # 清空 w 的梯度（PyTorch 默认累积梯度，必须手动清零）
    b.grad.zero_()  # 清空 b 的梯度

    if (epoch + 1) % 40 == 0:  # 每 40 轮打印一次
        print(f"第 {epoch+1:3d} 轮 | loss={loss.item():.4f} | w={w.item():.4f} | b={b.item():.4f}")

print(f"\n训练完成：w ≈ {w.item():.3f}（目标 3），b ≈ {b.item():.3f}（目标 2）")
```

### 第一部分：自动求导基础（第 8~12 行）

这部分用一个最简单的一元函数 `y = x² + 3x + 1`，演示"定义自变量 → 前向计算 → 反向传播 → 取梯度"的完整流程。

```python
x = torch.tensor(2.0, requires_grad=True)  # 创建一个需要追踪梯度的标量张量
```

- `torch.tensor(2.0, requires_grad=True)` —— 创建一个值为 `2.0` 的**标量**张量（没有形状，就是一个数）。`requires_grad=True` 是关键参数：它告诉 PyTorch "请记录这个张量参与的所有运算，稍后我要对它求导"。如果省略这个参数（默认 `False`），后面调用 `y.backward()` 会直接报错。注意这里用 `2.0`（浮点数）而不是 `2`（整数），因为 PyTorch 只对浮点类型的张量求梯度，用整数会报 `RuntimeError: Only Tensors of floating point dtype can require gradients`。

```python
y = x ** 2 + 3 * x + 1  # 定义函数 y = x² + 3x + 1，PyTorch 会自动记录计算图
```

- `y = x ** 2 + 3 * x + 1` —— 计算 `y = x² + 3x + 1`。代入 `x = 2`，得到 `y = 4 + 6 + 1 = 11`。因为 `x` 开启了梯度追踪，PyTorch 会在后台记录"`y` 是由 `x` 经过平方、乘法、加法得到的"这张**计算图**。`y` 此时也是一个张量，并且自动带有梯度信息（`y.requires_grad` 为 `True`），不需要我们手动设置。

```python
y.backward()  # 反向传播：计算 y 对 x 的导数 dy/dx = 2x + 3
```

- `y.backward()` —— 触发反向传播。PyTorch 沿着记录好的计算图，用链式法则从 `y` 一路往回算出 `y` 对 `x` 的导数。数学上 `dy/dx = 2x + 3`，代入 `x = 2` 应得 `7`。注意：`backward()` 通常只在**标量**（单个数值）上直接调用；如果 `y` 是多元素张量，需要额外传入一个权重参数，这是新手常踩的坑。

```python
print("x = 2 时，dy/dx =", x.grad)  # x.grad 保存梯度 -> 2*2+3 = 7
```

- `x.grad` —— `backward()` 算出的梯度存放在"叶子节点"（我们手动创建的、开启了 `requires_grad` 的张量）的 `.grad` 属性里。这里打印出 `tensor(7.)`，和手工推导的 `2×2+3=7` 完全一致。注意返回的是一个张量 `tensor(7.)` 而不是普通的 Python 数字 `7.0`。

### 第二部分：手写梯度下降拟合 y = 3x + 2（第 14~42 行）

这部分是本章的核心：我们造一批满足 `y = 3x + 2`（带噪声）的数据，然后从随机参数出发，用梯度下降把 `w` 和 `b` 一步步"学"回来。

#### 固定随机种子（第 15 行）

```python
torch.manual_seed(42)  # 固定随机种子，保证每次运行结果一致（可复现）
```

- `torch.manual_seed(42)` —— 设置随机数生成器的种子。下面生成数据和初始化参数都会用到随机数，固定种子后，任何人、任何时间运行这段代码，生成的数据和初始参数都一模一样，训练结果完全可复现。`42` 只是惯例数字，换成别的整数也可以。**竞赛提交代码时固定随机种子是好习惯**，能保证评委复现出和你一样的结果。

#### 生成数据（第 17~19 行）

```python
X = torch.rand(100, 1) * 10  # 100 个 0~10 之间的随机数作为输入，形状 (100,1)
```

- `torch.rand(100, 1)` —— 生成形状为 `(100, 1)` 的张量，每个元素是 `[0, 1)` 区间均匀分布的随机数。可以把它理解为 100 行 1 列的表格，即 100 个样本、每个样本 1 个特征。
- `* 10` —— 把每个数放大 10 倍，得到 `[0, 10)` 区间的随机输入。这里利用了第 1 章学过的**广播机制**：标量 `10` 自动扩展到每个元素上。

```python
y_true = 3 * X + 2 + torch.randn(100, 1)  # 真实标签 = 3x+2 加随机噪声
```

- `3 * X + 2` —— 先按真实规律算出 `y = 3x + 2`，形状仍是 `(100, 1)`。
- `torch.randn(100, 1)` —— 生成形状 `(100, 1)` 的**标准正态分布**（均值 0、标准差 1）随机数，模拟现实世界数据中不可避免的测量噪声。这正是赛项知识点中"概率论与统计学"的体现：真实数据永远不会完美落在直线上。
- 整行合起来：`y_true` 是带有噪声的真实标签。我们的模型只知道 `X` 和 `y_true`，并不知道背后的 `3` 和 `2`，要靠梯度下降把它们"猜"出来。

#### 初始化待学习的参数（第 21~23 行）

```python
w = torch.randn(1, requires_grad=True)  # 权重，随机初始化，需要梯度
```

- `torch.randn(1, ...)` —— 创建只含 1 个随机数的张量作为权重 `w` 的初始值。**为什么随机初始化？** 因为如果从 0 或固定值开始，在更复杂的网络里所有神经元会学到一模一样的东西（对称性无法打破）；从随机值出发是深度学习的惯例。
- `requires_grad=True` —— 声明 `w` 是需要学习的参数，PyTorch 会追踪它的运算并为它求梯度。

```python
b = torch.zeros(1, requires_grad=True)  # 偏置，初始化为 0，需要梯度
```

- `torch.zeros(1, ...)` —— 创建值为 0 的张量作为偏置 `b` 的初始值。偏置从 0 开始是安全的惯例（偏置不存在对称性问题）。
- 常见坑：忘记给参数加 `requires_grad=True`，会导致 `loss.backward()` 后 `w.grad` 是 `None`，更新时直接报错。

#### 设置学习率（第 25 行）

```python
learning_rate = 0.01  # 学习率：每次参数更新的步长（赛项考点：影响训练稳定性）
```

- `learning_rate = 0.01` —— 定义学习率，即每次参数更新的**步长**。梯度的方向告诉我们"往哪边走"，学习率决定"这一步迈多远"。`0.01` 是一个常用的保守起点。它是本章引入的第一个**超参数**（需要人为设定、而不是模型自己学出来的参数），也是赛项明确考点：学习率太小训练慢，太大会震荡甚至发散，本章最后的动手练习会让你直观感受这一点。

#### 训练循环（第 27~40 行）

```python
for epoch in range(200):  # 训练 200 轮（epoch = 遍历一遍全部数据）
```

- `for epoch in range(200)` —— 开始训练循环，共 200 轮。**epoch**（轮次）是训练术语，指"把全部训练数据完整过一遍"。这里每轮都用全部 100 个样本计算损失，所以循环 200 次就是 200 个 epoch。`epoch` 变量取值从 0 到 199。

```python
    y_pred = w * X + b  # 前向传播：用当前参数做预测
```

- `y_pred = w * X + b` —— **前向传播**：用当前的 `w` 和 `b` 对全部 100 个样本同时做预测，即计算 `y = wx + b`。形状变化：`w` 是 `(1,)`，`X` 是 `(100, 1)`，乘法通过广播得到 `(100, 1)`，再加 `b`（广播）结果仍是 `(100, 1)`。这一行同时完成了 100 次预测，没有写任何 `for` 循环——这是张量运算的威力，称为**向量化**。

```python
    loss = ((y_pred - y_true) ** 2).mean()  # 均方误差损失 MSE
```

- `y_pred - y_true` —— 每个样本的预测误差，形状 `(100, 1)`。
- `** 2` —— 误差逐元素平方，消除正负号并放大大误差。
- `.mean()` —— 对全部 100 个平方误差取平均，得到一个**标量**（这就是 MSE 均方误差）。`loss` 必须最终是标量，因为"梯度"描述的是单个数值（总损失）对每个参数的影响。

```python
    loss.backward()  # 反向传播：自动计算 loss 对 w、b 的梯度
```

- `loss.backward()` —— 本章的魔法所在。PyTorch 沿着计算图自动算出 `loss` 对 `w` 和 `b` 的梯度，分别存入 `w.grad` 和 `b.grad`。以 MSE 为例，数学上 `∂loss/∂w = 2·mean((y_pred - y_true)·X)`，但**我们不需要手写这个公式**，框架全包了——这正是 Autograd 存在的意义。网络再复杂（几百万参数、几十层），也只需要这一行。

```python
    with torch.no_grad():  # 参数更新不需要记录计算图，用 no_grad 关闭追踪
```

- `with torch.no_grad():` —— 开启一个上下文，其中的所有运算**不被记录**到计算图。为什么需要它？因为 `w -= lr * w.grad` 这步更新纯粹是"修改参数的值"，不是前向传播的一部分；如果被记录下来，计算图会越滚越大、浪费内存，而且下一轮对 `w` 求梯度时会把更新步骤也算进去，导致梯度错误。这是新手必踩的经典坑。

```python
        w -= learning_rate * w.grad  # 梯度下降更新 w：w = w - lr * 梯度
```

- `w -= learning_rate * w.grad` —— 梯度下降的核心公式：`新w = 旧w − 学习率 × 梯度`。为什么用减号？因为梯度指向损失**上升**最快的方向，反方向才是下降最快的方向。举例：若 `w.grad = -4.6`（增大 `w` 会让损失减小），那么 `w -= 0.01 × (-4.6)` 等于 `w += 0.046`，`w` 变大，损失随之下降——方向完全正确。

```python
        b -= learning_rate * b.grad  # 梯度下降更新 b
```

- `b -= learning_rate * b.grad` —— 同理更新偏置 `b`：`新b = 旧b − 学习率 × b的梯度`。

```python
    w.grad.zero_()  # 清空 w 的梯度（PyTorch 默认累积梯度，必须手动清零）
```

- `w.grad.zero_()` —— 把 `w` 的梯度清零。**这是最容易被忘记、也最致命的一步**：PyTorch 的设计是每次 `backward()` 会把新梯度**加到** `.grad` 的原有值上（这样设计是为了支持梯度累积等高级技巧）。如果不清零，第二轮的梯度会叠在第一轮上，参数更新步长越滚越大，训练直接失控。方法名末尾的下划线 `_` 是 PyTorch 的命名约定，表示"就地修改"（直接改张量本身，不返回新张量）。

```python
    b.grad.zero_()  # 清空 b 的梯度
```

- `b.grad.zero_()` —— 同理清空 `b` 的梯度。每个带 `requires_grad=True` 且参与了本轮计算的参数，都要清零。

```python
    if (epoch + 1) % 40 == 0:  # 每 40 轮打印一次
```

- `(epoch + 1) % 40 == 0` —— `%` 是取余运算。因为 `epoch` 从 0 开始计数，所以用 `epoch + 1` 让它对应人类习惯的"第几轮"：当轮数为 40、80、120、160、200 时条件成立，每 40 轮打印一次进度。200 轮全打印会刷屏，不打又看不见进展，每 40 轮一次是常见的折中。

```python
        print(f"第 {epoch+1:3d} 轮 | loss={loss.item():.4f} | w={w.item():.4f} | b={b.item():.4f}")
```

- `f"..."` —— f-string 格式化字符串，花括号里的表达式会被替换成实际值。
- `{epoch+1:3d}` —— 打印轮次，`:3d` 表示按整数格式、占 3 个字符宽度（不足补空格），让输出中"第 40 轮"和"第 200 轮"右对齐，整齐美观。
- `loss.item()` —— `.item()` 把只含一个元素的张量转换成普通的 Python 浮点数。打印张量本身会带上 `tensor(...)` 外壳和梯度信息，既不美观也无法用 `:.4f` 控制小数位，所以先取数值。
- `:.4f` —— 保留 4 位小数。`w.item()`、`b.item()` 同理。

#### 打印最终结果（第 42 行）

```python
print(f"\n训练完成：w ≈ {w.item():.3f}（目标 3），b ≈ {b.item():.3f}（目标 2）")
```

- `\n` —— 换行符，先空一行再打印，视觉上和前面的训练日志分开。
- `{w.item():.3f}` —— 取出训练结束后的 `w`，保留 3 位小数打印。最终 `w` 应该接近真实值 3，`b` 应该接近真实值 2。由于数据中加了噪声，`b` 与 2 存在一定偏差是正常的（噪声会把直线的截距"顶偏"）。

## 运行结果与解读

```text

第  40 轮 | loss=1.0779 | w=3.1452 | b=0.9334
第  80 轮 | loss=0.9459 | w=3.1119 | b=1.1596

```

逐项解读：

- **`x = 2 时，dy/dx = tensor(7.)`** —— 第一部分的结果。手工推导 `dy/dx = 2x + 3`，代入 `x = 2` 得 7，PyTorch 算出的梯度 `tensor(7.)` 与之完全一致。看到这一行就说明你已经掌握了 `requires_grad` + `backward()` + `.grad` 这套自动求导流程。注意输出是 `tensor(7.)`，是 0 维张量而非裸数字。

- **loss 从 1.0779 单调下降到 0.7528** —— 每一轮梯度下降都在让损失变小，说明梯度方向算对了、学习率选得合适。loss 没有变成 0 是因为数据里加了噪声：最好的直线也不可能穿过所有带噪声的点，剩余的 loss 基本就是噪声本身的方差。**看到 loss 持续下降并趋于平稳，就是训练正常的标志**；如果 loss 上下乱跳或变成 `nan`，通常意味着学习率太大。

- **w 从 3.1452 缓步降到 3.0428，逼近目标 3** —— `w` 的随机初始值恰好离 3 不远，所以它只需要小幅修正。每一轮都在靠近，但步子越来越小——因为越接近最优值，梯度越小，这正是梯度下降"自动刹车"的特性。

- **b 从 0.9334 一路爬升到 1.6278，向目标 2 靠近** —— `b` 从 0 出发，要走的路更远，所以 200 轮结束时（1.6278）离目标 2 还有一段距离。这直观地说明：**梯度下降是一步步逼近的迭代过程，训练轮数不够时参数还没走到头**。如果再增加轮数，`b` 会继续向 2 靠拢。

- **`训练完成：w ≈ 3.043（目标 3），b ≈ 1.628（目标 2）`** —— 总结行。`w` 已经非常接近真实值 3；`b` 没到 2，一部分原因是轮数有限，另一部分原因是噪声会把截距的估计带偏——这是统计学上的正常现象，不是代码错误。学会区分"代码错了"和"训练尚未收敛"，是人工智能训练师的基本功。

## 小结

1. **Autograd 三件套**：`requires_grad=True` 声明要追踪，`loss.backward()` 自动算梯度，结果存在 `参数.grad` 里。推导梯度公式的活儿，框架全包了。
2. **梯度下降核心公式**：`参数 = 参数 − 学习率 × 梯度`，沿梯度反方向走，损失下降最快。
3. **训练循环五步曲**：前向算预测 → 算损失 → `backward()` 求梯度 → `no_grad` 下更新参数 → `zero_()` 清梯度，循环往复。这五步是所有深度学习训练的骨架，后续章节只是把它封装得更漂亮。
4. **两个新手大坑**：更新参数忘了包 `torch.no_grad()`；每轮结束忘了 `grad.zero_()`（PyTorch 默认累积梯度，不清零训练必崩）。
5. **学习率（lr）是步长**：太小训练慢，太大震荡发散。本章 `0.01` 是稳妥值，它是竞赛调参的核心超参数。
