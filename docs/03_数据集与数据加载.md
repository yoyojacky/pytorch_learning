## 核心概念讲解

**脏数据（dirty data）**：真实世界里采集到的数据几乎从来不是干净的。常见的问题有两类：一是**缺失值**，某些数据没有采集到，在程序里常表示为 `NaN`（Not a Number，非数字）；二是**异常值**，比如传感器故障导致某个数值变成了 999 这种明显离谱的数。脏数据如果不处理就直接喂给模型，轻则拉低准确率，重则让训练直接崩溃（NaN 参与运算会"传染"，把所有结果都变成 NaN）。

**数据清洗**：把含脏数据的样本找出来并剔除（或用合理值填充）。本章采用最直接的策略——整行剔除。

**标准化（Standardization / Z-score）**：不同特征的数值范围可能差很多（比如"年龄"是 0~100，"年收入"是 0~1000000），数值范围大的特征会在训练中"嗓门过大"，掩盖其他特征的作用。标准化把每个特征按公式

```
x' = (x - μ) / σ
```

变换，其中 `μ`（mu）是该特征的均值，`σ`（sigma）是该特征的标准差。变换后每个特征的均值约为 0、标准差约为 1，所有特征站在同一起跑线上。

**数据增强（data augmentation）**：在训练时对样本做轻微扰动（本章是给特征加少量随机噪声），相当于"凭空造出"略有差异的新样本，让模型见得更多、更不容易死记硬背训练数据（即缓解过拟合）。注意：**只有训练集做增强，测试集必须保持原样**，否则评估结果就不真实了。

**Dataset**：PyTorch 定义的数据集"标准接口"。任何数据集类只要继承它并实现两个方法——`__len__`（返回样本总数）和 `__getitem__`（按索引取一个样本）——就能接入 PyTorch 的整个数据生态。

**DataLoader**：包在 Dataset 外面的"传送带"。它负责自动把样本按 `batch_size`（批大小）分成一批一批，还能在每个 epoch（轮次，指把全部训练数据完整过一遍）开始时打乱顺序。模型训练时一次喂一小批数据而不是一条或全部，这种方式叫**小批量训练（mini-batch）**，是深度学习的主流做法。

## 完整代码

```python
"""
第 3 章：数据工程 —— Dataset 与 DataLoader
对应赛项知识点：构建结构化数据集，完成数据清洗和增强处理；
数据清洗、标准化及增强技术，确保数据质量符合模型输入要求
"""
import torch  # 导入 PyTorch
from torch.utils.data import Dataset, DataLoader  # Dataset 定义数据集，DataLoader 批量加载

torch.manual_seed(42)  # 固定随机种子保证可复现

# ========== 1. 模拟一份"脏数据"（数据工程的真实场景） ==========
raw_X = torch.randn(120, 4)  # 120 个样本，每个 4 个特征
raw_y = (raw_X[:, 0] + raw_X[:, 1] > 0).long()  # 标签：前两个特征之和>0 为 1，否则为 0

raw_X[5] = float("nan")  # 故意制造第 5 个样本为缺失值 NaN（脏数据）
raw_X[20] = 999.0  # 故意制造第 20 个样本为异常值 999（脏数据）

# ========== 2. 数据清洗：剔除含 NaN 或异常值的样本 ==========
mask = ~torch.isnan(raw_X).any(dim=1)  # dim=1 按行检查，any 表示该行任一特征为 NaN 就标记
mask &= (raw_X.abs().max(dim=1).values < 100)  # 再叠加条件：该行所有特征绝对值都要 < 100
X_clean = raw_X[mask]  # 布尔索引：只保留干净样本
y_clean = raw_y[mask]  # 标签同步过滤（特征和标签必须一一对应）
print(f"清洗前 {len(raw_X)} 条 -> 清洗后 {len(X_clean)} 条")  # 120 -> 118

# ========== 3. 标准化（Z-score）：均值 0、标准差 1 ==========
mean = X_clean.mean(dim=0)  # dim=0 按列求均值 -> 每个特征的均值
std = X_clean.std(dim=0)  # 每个特征的标准差
X_std = (X_clean - mean) / std  # 标准化公式：(x - μ) / σ
print("标准化后各特征均值≈0:", X_std.mean(dim=0).round())  # 验证结果

# ========== 4. 自定义 Dataset（PyTorch 数据的标准封装方式） ==========
class MyDataset(Dataset):  # 继承 Dataset 类，必须实现两个方法
    def __init__(self, X, y, augment=False):  # 初始化：传入特征、标签、是否做数据增强
        self.X = X  # 保存特征张量
        self.y = y  # 保存标签张量
        self.augment = augment  # 记录是否启用数据增强

    def __len__(self):  # 必须实现：返回数据集总样本数
        return len(self.X)

    def __getitem__(self, idx):  # 必须实现：根据索引 idx 取出一个样本
        x = self.X[idx]  # 取第 idx 个特征
        if self.augment:  # 训练时启用数据增强
            x = x + torch.randn_like(x) * 0.05  # 加 5% 高斯噪声，模拟数据增强
        return x, self.y[idx]  # 返回 (特征, 标签) 对

# ========== 5. 划分训练集/测试集 ==========
n_train = 100  # 前 100 条做训练，剩余做测试
train_set = MyDataset(X_std[:n_train], y_clean[:n_train], augment=True)  # 训练集启用增强
test_set = MyDataset(X_std[n_train:], y_clean[n_train:], augment=False)  # 测试集不增强！

# ========== 6. DataLoader：自动分批、打乱 ==========
train_loader = DataLoader(train_set, batch_size=16, shuffle=True)  # 每批 16 条，每轮打乱顺序
test_loader = DataLoader(test_set, batch_size=16, shuffle=False)  # 测试集无需打乱

for batch_X, batch_y in train_loader:  # 遍历 DataLoader，一次取一个批次
    print("一个批次的特征形状:", batch_X.shape)  # torch.Size([16, 4])
    print("一个批次的标签形状:", batch_y.shape)  # torch.Size([16])
    break  # 只看第一个批次就退出循环
```

### 第 1 部分：模拟一份"脏数据"

```python
raw_X = torch.randn(120, 4)  # 120 个样本，每个 4 个特征
```

- `torch.randn(120, 4)` —— 生成一个形状为 `(120, 4)` 的张量，每个元素都是从标准正态分布（均值 0、标准差 1）中随机抽取的数。我们用表格的视角看它：120 行代表 120 个样本，4 列代表每个样本有 4 个特征。`raw_` 前缀表示这是"原始的、未处理的"数据。

```python
raw_y = (raw_X[:, 0] + raw_X[:, 1] > 0).long()  # 标签：前两个特征之和>0 为 1，否则为 0
```

- `raw_X[:, 0]` —— 切片取所有行的第 0 列（`:` 表示"这一维全要"），得到形状 `(120,)` 的一维张量，即每个样本的第 1 个特征。
- `raw_X[:, 0] + raw_X[:, 1]` —— 把第 0 列和第 1 列逐元素相加，得到 120 个"前两特征之和"。
- `... > 0` —— 逐元素比较，得到一个布尔（True/False）张量：和大于 0 的位置为 `True`。
- `.long()` —— 把布尔张量转成 64 位整数类型，`True` 变 `1`、`False` 变 `0`。这样就人为构造了一个二分类问题的标签：每个样本要么属于类别 1，要么属于类别 0。整行一气呵成，是 PyTorch 里很典型的"向量化"写法——不写 for 循环就能处理全部 120 个样本。

```python
raw_X[5] = float("nan")  # 故意制造第 5 个样本为缺失值 NaN（脏数据）
```

- `raw_X[5] = float("nan")` —— 把第 5 行（第 6 个样本）的整行 4 个特征都赋值为 `NaN`。`float("nan")` 是 Python 里表示"非数字"的特殊浮点值，常用来标记缺失数据。这里故意制造脏数据，模拟真实采集中的缺失。注意：`NaN` 有个反直觉的特性——它不等于任何数，包括它自己（`nan == nan` 的结果是 `False`），所以检测缺失值必须用 `torch.isnan`，不能用 `==` 比较。

```python
raw_X[20] = 999.0  # 故意制造第 20 个样本为异常值 999（脏数据）
```

- `raw_X[20] = 999.0` —— 把第 20 行整行赋值为 999。正常数据来自标准正态分布，绝大多数取值在 -3 到 3 之间，999 明显是个"离谱"的异常值（比如传感器故障时常见的占位值）。这行模拟异常值类型的脏数据。

### 第 2 部分：数据清洗

```python
mask = ~torch.isnan(raw_X).any(dim=1)  # dim=1 按行检查，any 表示该行任一特征为 NaN 就标记
```

- `torch.isnan(raw_X)` —— 逐元素检查是否为 `NaN`，返回与 `raw_X` 同形状 `(120, 4)` 的布尔张量：是 `NaN` 的位置为 `True`。这就是上一条说的"检测 NaN 必须用专门函数"。
- `.any(dim=1)` —— 沿着第 1 维（也就是按行、跨 4 个特征）做"逻辑或"归约：只要这一行有任意一个特征是 `NaN`，该行结果就是 `True`。返回形状 `(120,)` 的布尔张量，`True` 表示"这行有缺失值"。`dim=1` 是关键：dim=0 会按列检查，含义就完全不同了。
- `~...` —— 波浪号是按位取反，对布尔张量就是"逻辑非"：`True` 变 `False`、`False` 变 `True`。取反后 `True` 表示"这行没有缺失值"。
- 整行的结果：`mask` 是形状 `(120,)` 的布尔张量，`True` 代表"这一行干净、可以保留"。目前第 5 行是 `False`，其余是 `True`。

```python
mask &= (raw_X.abs().max(dim=1).values < 100)  # 再叠加条件：该行所有特征绝对值都要 < 100
```

- `raw_X.abs()` —— 逐元素取绝对值，形状仍为 `(120, 4)`。取绝对值是因为异常值可能是很大的正数或很小的负数（如 ±999），用绝对值一把抓。
- `.max(dim=1)` —— 沿第 1 维（按行）取最大值，返回的不是单纯张量，而是一个含 `.values` 和 `.indices` 两个属性的具名元组：`.values` 是每行的最大值（形状 `(120,)`），`.indices` 是最大值所在的列号。这里只关心数值，所以下一步取 `.values`。
- `.values < 100` —— 逐元素比较，得到布尔张量：`True` 表示"这行连最大的绝对值都不到 100"，即整行都在正常范围内。阈值 100 是人为设定的业务判断：正常数据在 ±3 左右，100 已经足够宽松，只会拦住 999 那种离谱值。
- `mask &= ...` —— 等价于 `mask = mask & (...)`。`&` 是逐元素"逻辑与"，把新条件叠加到原掩码上：一行必须同时满足"无 NaN"且"无异常值"才是 `True`。注意：PyTorch 布尔张量之间的与、或要用 `&`、`|`（并加好括号），不能用 Python 的 `and`、`or`，否则报错。
- 这行执行后，第 20 行也变成了 `False`，mask 中共有 2 个 `False`。

```python
X_clean = raw_X[mask]  # 布尔索引：只保留干净样本
```

- `raw_X[mask]` —— 这是 PyTorch/NumPy 里非常常用的**布尔索引**：用一个 `(120,)` 的布尔张量去索引 `(120, 4)` 的张量，结果是把所有 `True` 对应的行挑出来，组成新张量。118 行为 `True`，所以 `X_clean` 的形状是 `(118, 4)`。注意布尔索引返回的是**新张量**（原数据不会被改动）。

```python
y_clean = raw_y[mask]  # 标签同步过滤（特征和标签必须一一对应）
```

- `raw_y[mask]` —— 用**同一个掩码**过滤标签，得到形状 `(118,)` 的 `y_clean`。这步绝不能漏：特征删掉了第 5、20 两行，标签也必须删掉对应的两行，否则第 5 个特征就会对上第 6 个标签，"张冠李戴"，数据全部错位——这是数据清洗中最常见的低级错误。

```python
print(f"清洗前 {len(raw_X)} 条 -> 清洗后 {len(X_clean)} 条")  # 120 -> 118
```

- `len(raw_X)` / `len(X_clean)` —— 对张量用 `len()` 得到第 0 维的大小（行数），即样本数，分别是 120 和 118。
- `f"..."` —— Python 的 f-string 格式化字符串，花括号里的表达式会被替换成实际值。这行打印清洗前后的样本数对比，让读者直观看到清洗剔除了 2 条脏数据。养成在数据处理每一步打印形状/数量的习惯，能帮你尽早发现错误。

### 第 3 部分：标准化（Z-score）

```python
mean = X_clean.mean(dim=0)  # dim=0 按列求均值 -> 每个特征的均值
```

- `X_clean.mean(dim=0)` —— 沿第 0 维（按列、跨 118 个样本）求均值，返回形状 `(4,)` 的张量，4 个数分别是 4 个特征各自的均值。注意和上一节清洗时的 `dim=1`（按行）对比记忆：矩阵里 `dim=0` 是"纵向上把行压扁"，`dim=1` 是"横向上把列压扁"。

```python
std = X_clean.std(dim=0)  # 每个特征的标准差
```

- `X_clean.std(dim=0)` —— 同样按列求标准差，返回形状 `(4,)` 的张量。标准差衡量数据的离散程度，标准化的除法要用它把每个特征的"波动幅度"统一成 1。

```python
X_std = (X_clean - mean) / std  # 标准化公式：(x - μ) / σ
```

- `(X_clean - mean)` —— `X_clean` 形状 `(118, 4)`，`mean` 形状 `(4,)`，形状不同却能相减，靠的是**广播（broadcasting）**机制：`(4,)` 会被自动"复制"成 118 份，逐行相减，效果相当于每个元素都减去自己所在列的均值。
- `... / std` —— 同理，逐元素除以所在列的标准差。
- 整行就是标准化公式 `(x - μ) / σ` 的向量化实现，对全部 118×4 个元素一次算完，无需任何循环。结果 `X_std` 形状仍是 `(118, 4)`，但每列的均值约为 0、标准差约为 1。
- 工程提示（本章未演示但比赛常用）：严格做法应只用训练集计算 `mean` 和 `std`，再用它们去变换测试集，避免测试集的信息"泄漏"进训练过程。

```python
print("标准化后各特征均值≈0:", X_std.mean(dim=0).round())  # 验证结果
```

- `X_std.mean(dim=0)` —— 对标准化后的数据再按列求一次均值，理论上应该全是 0。
- `.round()` —— 逐元素四舍五入到整数。因为浮点运算有微小误差，直接打印会看到 `1.3e-08` 这类科学计数法的小数，四舍五入后能干净地显示为 `0.`（其中 `-0.` 是浮点数里"极小的负数四舍五入"的正常现象，与 `0.` 数值相等，不用慌）。
- 这行属于"自验证"：处理完数据立刻检查一遍是否符合预期，是数据工程的良好习惯。

### 第 4 部分：自定义 Dataset

```python
class MyDataset(Dataset):  # 继承 Dataset 类，必须实现两个方法
```

- `class MyDataset(Dataset):` —— 定义一个叫 `MyDataset` 的新类，括号里的 `Dataset` 表示**继承**自 PyTorch 的 `Dataset` 基类。继承的含义是：`MyDataset` 自动获得父类的通用能力（比如后续和 `DataLoader` 配合），我们只需补上自己数据集特有的两个方法。PyTorch 约定俗成：任何自定义数据集都必须实现 `__len__` 和 `__getitem__`，少了任何一个，DataLoader 都会报错。

```python
    def __init__(self, X, y, augment=False):  # 初始化：传入特征、标签、是否做数据增强
```

- `def __init__(self, X, y, augment=False):` —— 定义构造函数，创建 `MyDataset(...)` 对象时自动调用。`self` 指对象自身（Python 惯例，调用时不用手动传）；`X`、`y` 是传入的特征和标签张量；`augment=False` 是带默认值的关键字参数——不传它时默认不做数据增强，传 `augment=True` 则开启。

```python
        self.X = X  # 保存特征张量
        self.y = y  # 保存标签张量
        self.augment = augment  # 记录是否启用数据增强
```

- `self.X = X` —— 把传入的特征张量存为对象的属性，之后其他方法（如 `__getitem__`）可以通过 `self.X` 访问。不加 `self.` 的普通变量在函数结束后就消失了。
- `self.y = y` —— 同理，保存标签张量。
- `self.augment = augment` —— 同理，保存增强开关。把配置也存成属性，是"对象自己记住自己的状态"的面向对象写法。

```python
    def __len__(self):  # 必须实现：返回数据集总样本数
        return len(self.X)
```

- `def __len__(self):` —— 定义 Python 的"双下划线"特殊方法 `__len__`。它的妙处是：之后对数据集对象调用内置函数 `len(train_set)` 时，Python 会自动转调这个方法。DataLoader 内部也靠它得知数据集一共有多少条样本、能分出多少个批次。
- `return len(self.X)` —— 返回特征张量第 0 维的大小，即样本总数。注意必须返回整数。

```python
    def __getitem__(self, idx):  # 必须实现：根据索引 idx 取出一个样本
```

- `def __getitem__(self, idx):` —— 定义取下标的特殊方法。之后写 `train_set[3]` 时，Python 会自动调用它并传入 `idx=3`。DataLoader 每个批次正是反复调用 `dataset[idx]` 收集样本再拼成批次张量的。这是整个 Dataset 接口的核心：**数据如何被取出一条，完全由你在这里定义**（本章数据已在内存中所以很简单；真实项目里常在这里读图片文件、做解码）。

```python
        x = self.X[idx]  # 取第 idx 个特征
```

- `x = self.X[idx]` —— 用索引 `idx` 从特征张量里取出第 `idx` 行，得到形状 `(4,)` 的一维张量（单个样本的 4 个特征）。先用局部变量 `x` 接住，是因为接下来可能要对它做增强处理。

```python
        if self.augment:  # 训练时启用数据增强
            x = x + torch.randn_like(x) * 0.05  # 加 5% 高斯噪声，模拟数据增强
```

- `if self.augment:` —— 判断创建数据集时有没有打开增强开关。增强只在训练集开启，测试集走 `False` 分支直接跳过。
- `torch.randn_like(x)` —— 生成一个与 `x` 形状和数据类型完全相同、元素来自标准正态分布的随机张量（形状 `(4,)`）。`*_like` 系列函数（还有 `zeros_like`、`ones_like`）的好处是不用关心 `x` 的形状，跟着走就行。
- `* 0.05` —— 把噪声的幅度缩小到约 5%。标准化后数据的标准差是 1，乘以 0.05 意味着扰动幅度约为数据本身波动的二十分之一——足以让样本"略有不同"，又不会改变样本的本质含义。噪声加太大反而会污染数据，这个系数是个需要权衡的超参数。
- `x = x + ...` —— 把噪声叠加到原特征上，得到"新"样本。每次取同一个 `idx`，噪声都是重新随机生成的，所以模型在不同 epoch 看到的同一样本都有细微差别——这正是增强能防过拟合的原因。

```python
        return x, self.y[idx]  # 返回 (特征, 标签) 对
```

- `return x, self.y[idx]` —— 返回一个元组：第 0 项是（可能加了噪声的）特征，第 1 项是对应的标签。DataLoader 收集一个批次的多个返回值后，会自动把各样本的特征拼成 `(batch_size, 4)` 的张量、标签拼成 `(batch_size,)` 的张量——这就是 `__getitem__` 返回格式决定批次格式的道理。

### 第 5 部分：划分训练集/测试集

```python
n_train = 100  # 前 100 条做训练，剩余做测试
```

- `n_train = 100` —— 设定训练集大小为 100 条。清洗后共 118 条，所以测试集是后 18 条。训练集用来"学习"，测试集用来"考试"，两者必须分开，否则就像用考过的题测学生——看不出真实水平。把数字写成有名字的变量而不是在切片里直接写 `100`，改起来更方便。

```python
train_set = MyDataset(X_std[:n_train], y_clean[:n_train], augment=True)  # 训练集启用增强
```

- `X_std[:n_train]` —— 切片取前 100 行标准化后的特征，形状 `(100, 4)`。注意切的是 `X_std`（标准化后的），不是 `X_clean`——模型应吃处理完的数据。
- `y_clean[:n_train]` —— 同样取前 100 个标签，与特征严格对齐。
- `augment=True` —— 训练集开启数据增强。
- 整行创建一个训练数据集对象 `train_set`，`len(train_set)` 为 100。

```python
test_set = MyDataset(X_std[n_train:], y_clean[n_train:], augment=False)  # 测试集不增强！
```

- `X_std[n_train:]` —— 切片取第 100 行到末尾，即剩下的 18 条特征，形状 `(18, 4)`。`[n_train:]` 省略结尾表示"一直取到最后"。
- `augment=False` —— 测试集**不增强**。评估时我们要测的是模型对真实、干净数据的判断力，加噪声会让评估结果不稳定且偏离真实水平。注释里的感叹号就是强调这个易错点。

### 第 6 部分：DataLoader 自动分批、打乱

```python
train_loader = DataLoader(train_set, batch_size=16, shuffle=True)  # 每批 16 条，每轮打乱顺序
```

- `DataLoader(train_set, ...)` —— 把训练数据集交给 DataLoader 包装。第一个位置参数必须是实现了 Dataset 接口的对象。
- `batch_size=16` —— 每个批次装 16 条样本。100 条样本会被分成 7 个批次（前 6 批各 16 条，最后一批 4 条；不满一批时默认照常给出，可用 `drop_last=True` 丢弃）。
- `shuffle=True` —— 每开始新的一轮（epoch）遍历前，先把样本顺序随机打乱。训练必须打乱：如果模型总按固定顺序看数据，容易学到"顺序"这种伪规律，每批数据的分布也更接近随机抽样，梯度下降更稳定。
- 返回的 `train_loader` 是一个可迭代对象，可以用 for 循环逐批取数据。

```python
test_loader = DataLoader(test_set, batch_size=16, shuffle=False)  # 测试集无需打乱
```

- 同样包装测试集，但 `shuffle=False`：评估时不关心顺序，且不打乱能让每次评估结果可对比、可复现。这里 `test_loader` 创建后本章没有使用它，属于为后续章节（训练与评估循环）搭好的脚手架。

```python
for batch_X, batch_y in train_loader:  # 遍历 DataLoader，一次取一个批次
```

- `for batch_X, batch_y in train_loader:` —— 开始遍历 DataLoader。每次循环，DataLoader 在后台做三件事：按打乱后的顺序取 16 个索引 → 调用 16 次 `train_set[idx]`（训练集开了增强，所以取出的样本带随机噪声）→ 把 16 个 `(特征, 标签)` 元组分别堆叠成批次张量。循环变量 `batch_X`、`batch_y` 用元组解包一次性接住这两个批次张量。

```python
    print("一个批次的特征形状:", batch_X.shape)  # torch.Size([16, 4])
```

- `batch_X.shape` —— 批次特征的形状。16 个样本、每个 4 维特征被堆叠成 `(16, 4)` 的二维张量。打印形状验证：`[16, 4]` 的第一个 16 正是 `batch_size`，第二个 4 正是特征数，说明 DataLoader 拼接正确。

```python
    print("一个批次的标签形状:", batch_y.shape)  # torch.Size([16])
```

- `batch_y.shape` —— 批次标签的形状，16 个标量标签堆叠成一维张量 `(16,)`（打印为 `[16]`）。它的第 0 维与 `batch_X` 的第 0 维一致——特征和标签按批次严格对齐。

```python
    break  # 只看第一个批次就退出循环
```

- `break` —— 立即退出 for 循环。本章只想验证 DataLoader 能正确给出一个批次，没有必要把 7 个批次全部打印一遍。实际训练时去掉 `break`，循环跑完所有批次就是一个 epoch。

## 运行结果与解读

本代码的真实运行输出如下（见 `docs/outputs/03_output.txt`）：

```text
清洗前 120 条 -> 清洗后 118 条
标准化后各特征均值≈0: tensor([0., -0., -0., 0.])
一个批次的特征形状: torch.Size([16, 4])
一个批次的标签形状: torch.Size([16])
```

逐项解读：

- **第 1 行 `清洗前 120 条 -> 清洗后 118 条`**：数据清洗剔除了恰好 2 条样本——正是我们故意污染的第 5 行（NaN）和第 20 行（999）。看到 120 变 118，说明 `isnan` 检查和绝对值阈值两道关卡都按预期工作了。如果这个数字不对（比如剩 120 条），多半是按位与 `&` 误写成了 `and`，或 `dim` 参数写反了。
- **第 2 行 `标准化后各特征均值≈0: tensor([0., -0., -0., 0.])`**：标准化后 4 个特征列的均值。四个值都是 0（`-0.` 是浮点舍入的正常现象，与 0 相等），证明 `(x - μ) / σ` 变换正确生效。这是数据处理中的"自检"输出，以后处理任何数据都可以模仿这一步验证。
- **第 3 行 `一个批次的特征形状: torch.Size([16, 4])`**：DataLoader 给出的第一个批次的特征形状。`16` 来自 `batch_size=16`，`4` 是特征数。看到这个形状，说明 Dataset 的 `__getitem__` 返回格式正确、DataLoader 堆叠成功。
- **第 4 行 `一个批次的标签形状: torch.Size([16])`**：同一批次的标签形状，16 个标签与 16 条特征一一对应。特征批次第 0 维和标签批次第 0 维相等，是后续训练时"每个样本都有正确答案"的基本保证。

四行输出共同确认了一条完整的数据流水线：脏数据被清洗 → 特征被标准化 → 数据被封装成 Dataset → DataLoader 能按批、按乱序供数据。走到这一步，数据就具备了直接送入模型训练的条件。

## 小结

- 真实数据先清洗再使用：用 `torch.isnan` 检测缺失值（NaN 不能用 `==` 判断），用绝对值阈值拦截异常值，用布尔索引剔除问题样本，**特征和标签必须用同一个掩码同步过滤**。
- 标准化公式 `(x - μ) / σ` 让每个特征均值约 0、标准差约 1，消除量纲差异；PyTorch 里用 `mean(dim=0)`、`std(dim=0)` 加广播一行搞定。
- 自定义 Dataset 只需继承 `Dataset` 并实现 `__len__`（返回样本数）和 `__getitem__`（按索引返回 `(特征, 标签)` 元组）两个方法。
- 数据增强写在 `__getitem__` 里，只在训练集开启（`augment=True`），测试集坚决不增强。
- `DataLoader` 负责分批（`batch_size`）和打乱（`shuffle=True` 仅用于训练集）；遍历它得到的 `batch_X` 形状是 `(batch_size, 特征数)`。

## 动手练习

1. **修改异常值阈值**：把清洗条件中的 `100` 改成 `2.0`，重新运行。观察清洗后剩余多少条样本，思考：阈值收得太紧会发生什么？（提示：标准正态分布下，约 5% 的数据绝对值超过 2）
2. **调整批大小并观察最后一批**：把 `batch_size=16` 改成 `batch_size=30`，并删掉最后的 `break`，把每个批次的形状都打印出来。观察 100 条样本被分成了几批、最后一批有多少条，理解 `batch_size` 与批次数量的关系。
3. **验证增强的随机性**：写两行 `print(train_set[0][0])`（连续取两次第 0 号训练样本的特征并打印），对比两次输出是否相同；再对 `test_set` 做同样操作。想想为什么一个变、一个不变。
