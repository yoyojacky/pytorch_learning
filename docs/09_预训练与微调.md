# 第 9 章：预训练与微调

## 本章目标

- 理解"预训练 + 微调"这一现代深度学习的核心范式：先在大数据上学通用能力，再迁移到小数据业务场景
- 学会用 `state_dict()` / `load_state_dict()` 把已训练好的模型参数迁移到新模型中
- 掌握"冻结参数"技术：通过 `requires_grad = False` 让部分网络层在训练中不更新
- 掌握"差异化学习率"技巧：为模型的不同部分设置不同的学习率（参数组 param groups）
- 能根据业务数据量的多少，在"冻结骨干微调"和"全量微调"两种方案之间做出合理选择

## 对应赛项知识点

本章对应"人工智能训练师"职业技能大赛的以下要求：**理解微调（Fine-tuning）技术如何通过领域特定数据调整模型参数，以适应业务场景需求**。

比赛中通常会给出这样的任务情境：企业有一批业务数据（数量往往不多），需要在现有预训练模型的基础上，通过微调让模型适应具体业务场景。你需要知道：如何加载预训练参数、如何替换任务相关的输出层、冻结与全量微调各自适用什么场景、以及为什么微调时要用比预训练更小的学习率。这些都是本章代码逐行覆盖的内容。

## 核心概念讲解

### 什么是预训练与微调

**预训练（Pre-training）**：先让模型在一个大规模、通用性强的数据集上训练，学会提取"通用特征"。比如 ResNet 在 ImageNet（上百万张图片）上学会了识别边缘、纹理、形状；BERT 在海量文本上学会了语言的语法和语义。

**微调（Fine-tuning）**：把预训练好的模型拿过来，在自己的小规模业务数据上继续训练。模型的"通用能力"被保留下来，只需少量数据就能适应新任务。

一个形象的类比：预训练像是让一个医学生完成多年全科学习，微调则是他进医院后用几周的科室轮转适应具体科室的工作——不需要从头学医，只需在已有基础上"转岗培训"。

本章用随机生成的小数据模拟这个流程：真实业务中骨干网络是 BERT/ResNet 这样的大模型，这里用一个三层小网络演示完全相同的操作步骤。

### 骨干网络与分类头

一个分类模型通常可以拆成两部分：

- **骨干（Backbone / features）**：前面的若干层，负责把原始输入加工成有意义的特征表示。
- **分类头（head）**：最后一层，把特征映射为类别得分。

微调的关键动作就是：**保留骨干，换掉分类头**。因为新任务的类别数往往和预训练任务不同（本章从 3 类换成 2 类），分类头的输出维度必须匹配新任务，所以它要重新初始化、重新训练。

### 参数迁移：state_dict

PyTorch 中每个模型的参数都可以用 `model.state_dict()` 导出为一个"字典"（键是参数名，值是张量），再用 `load_state_dict()` 灌进另一个结构相同的模型。这就是"把训练好的知识复制过来"的代码实现。

### 冻结参数：requires_grad = False

每个参数张量都有一个 `requires_grad` 开关。设为 `False` 后：

- 反向传播时不会为它计算梯度；
- 优化器更新时自然不会改动它。

冻结骨干 = 把预训练学到的特征提取能力"锁死"，只训练新换上的分类头。这叫**特征提取式微调**——把预训练模型当成一个固定的特征提取器。

### 差异化学习率（参数组）

`torch.optim.Adam` 等优化器除了接受一串参数，还接受一个"参数字典列表"，每个字典可以单独指定学习率。全量微调时的经典做法是：

```
骨干网络 → 小学习率（如 0.001）：慢慢调，别破坏已学到的知识
新分类头 → 大学习率（如 0.01）：它是随机初始化的，需要快速学习
```

### 两种微调方案的取舍

- **冻结骨干**：可训练参数少，不容易在小数据上过拟合（模型死记硬背训练数据、对新数据表现差），训练快、稳。适合数据很少的场景。
- **全量微调**：所有参数都可调，模型能更彻底地适应新任务，理论上上限更高，但需要更小心（小学习率），且数据太少时容易把骨干"带偏"。

## 完整代码

```python
"""
第 9 章：预训练与微调（Fine-tuning）
对应赛项知识点：理解微调（Fine-tuning）技术如何通过领域特定数据调整模型参数，
以适应业务场景需求
"""
import torch  # 导入 PyTorch
import torch.nn as nn  # 神经网络模块
from torch.utils.data import DataLoader, TensorDataset  # 数据工具

torch.manual_seed(42)  # 固定随机种子

# ========== 1. 场景设定 ==========
# "预训练"：模型在大规模通用数据上学会通用特征（这里用合成数据模拟）
# "微调"：把学到的通用能力迁移到具体的业务小数据集上
# 真实业务中：预训练模型是 BERT/ResNet 等，这里用小网络模拟同样的流程

# ========== 2. 第一步：模拟"预训练"—— 在通用数据上训练骨干网络 ==========
class Backbone(nn.Module):  # 骨干网络：负责提取通用特征
    def __init__(self):  # 构造函数
        super().__init__()  # 调用父类构造
        self.features = nn.Sequential(  # 特征提取部分
            nn.Linear(10, 64),  # 10 维输入 -> 64 维特征
            nn.ReLU(),  # 激活
            nn.Linear(64, 64),  # 64 -> 64
            nn.ReLU(),  # 激活
        )
        self.head = nn.Linear(64, 3)  # 预训练任务的分类头：3 个通用类别

    def forward(self, x):  # 前向传播
        feat = self.features(x)  # 提取特征
        return self.head(feat)  # 输出预训练任务的类别得分

pretrained = Backbone()  # 实例化待预训练的模型

# 模拟通用大数据集：1000 个样本，3 个类别
X_pre = torch.randn(1000, 10)  # 1000 个 10 维样本
y_pre = (X_pre[:, 0] * 2 + X_pre[:, 1] > 0).long() + (X_pre[:, 2] > 0).long()  # 3 类标签

pre_loader = DataLoader(TensorDataset(X_pre, y_pre), batch_size=32, shuffle=True)  # 加载器
optimizer = torch.optim.Adam(pretrained.parameters(), lr=0.01)  # 优化器
criterion = nn.CrossEntropyLoss()  # 损失函数

print("--- 阶段一：预训练（通用数据） ---")
for epoch in range(10):  # 预训练 10 轮
    for bx, by in pre_loader:  # 逐批次
        loss = criterion(pretrained(bx), by)  # 前向 + 损失
        optimizer.zero_grad()  # 清梯度
        loss.backward()  # 反向传播
        optimizer.step()  # 更新参数
print("预训练完成，骨干网络已学会通用特征\n")

# ========== 3. 第二步：微调 —— 迁移到业务小数据 ==========
# 业务场景：只有 80 个样本的 2 分类任务（数据少，从头训练效果差，微调是最佳选择）
X_task = torch.randn(80, 10)  # 80 个业务样本
y_task = (X_task[:, 0] + X_task[:, 2] > 0).long()  # 业务标签（2 类）
task_loader = DataLoader(TensorDataset(X_task, y_task), batch_size=16, shuffle=True)  # 加载器

# 方案 A：冻结骨干，只训练新的分类头（特征提取式微调）
model_a = Backbone()  # 新建模型
model_a.features.load_state_dict(pretrained.features.state_dict())  # 把预训练的骨干参数迁移过来
model_a.head = nn.Linear(64, 2)  # 换成业务任务的 2 分类头（输出维度必须匹配新任务）

for param in model_a.features.parameters():  # 遍历骨干网络的所有参数
    param.requires_grad = False  # 冻结：这些参数在训练中不更新（赛项考点）

optimizer_a = torch.optim.Adam(model_a.head.parameters(), lr=0.01)  # 优化器只管分类头的参数
print("--- 阶段二：微调（冻结骨干，只训练分类头） ---")
for epoch in range(20):  # 微调 20 轮
    for bx, by in task_loader:  # 逐批次
        loss = criterion(model_a(bx), by)  # 前向 + 损失
        optimizer_a.zero_grad()  # 清梯度
        loss.backward()  # 反向传播（被冻结的参数不会产生梯度更新）
        optimizer_a.step()  # 只更新分类头

with torch.no_grad():  # 评估
    acc_a = (model_a(X_task).argmax(1) == y_task).float().mean()  # 方案 A 准确率

# 方案 B：全量微调 —— 用更小的学习率更新所有参数
model_b = Backbone()  # 新建模型
model_b.features.load_state_dict(pretrained.features.state_dict())  # 迁移预训练骨干
model_b.head = nn.Linear(64, 2)  # 换分类头

optimizer_b = torch.optim.Adam([  # 为不同部分设置不同学习率（微调经典技巧）
    {"params": model_b.features.parameters(), "lr": 0.001},  # 骨干：小学习率，避免破坏已学知识
    {"params": model_b.head.parameters(), "lr": 0.01},  # 新分类头：大学习率，快速学习
])
print("--- 阶段二：全量微调（差异化学习率） ---")
for epoch in range(20):  # 训练 20 轮
    for bx, by in task_loader:  # 逐批次
        loss = criterion(model_b(bx), by)  # 前向 + 损失
        optimizer_b.zero_grad()  # 清梯度
        loss.backward()  # 反向传播
        optimizer_b.step()  # 更新所有参数

with torch.no_grad():  # 评估
    acc_b = (model_b(X_task).argmax(1) == y_task).float().mean()  # 方案 B 准确率

print(f"\n冻结骨干微调准确率: {acc_a:.2%}")
print(f"全量微调准确率:     {acc_b:.2%}")
print("结论：数据少时冻结骨干更稳；数据较多时全量微调（小学习率）通常上限更高。")
```

### 定义骨干网络

```python
class Backbone(nn.Module):  # 骨干网络：负责提取通用特征
```

- `class Backbone(nn.Module):` —— 定义一个名为 `Backbone`（骨干）的网络类，继承自 `nn.Module`。PyTorch 中所有自定义网络都要继承 `nn.Module`，这样才能自动获得参数注册、参数遍历、`state_dict` 导出等能力。

```python
    def __init__(self):  # 构造函数
        super().__init__()  # 调用父类构造
```

- `def __init__(self):` —— 构造函数，创建模型实例时自动执行，负责搭建网络结构。
- `super().__init__()` —— 调用父类 `nn.Module` 的构造函数。这一步**不能省略**，否则父类内部用于管理参数的簿记结构没有建立，后面注册层、训练、保存都会报错。

```python
        self.features = nn.Sequential(  # 特征提取部分
            nn.Linear(10, 64),  # 10 维输入 -> 64 维特征
            nn.ReLU(),  # 激活
            nn.Linear(64, 64),  # 64 -> 64
            nn.ReLU(),  # 激活
        )
```

- `self.features = nn.Sequential(...)` —— 把特征提取部分打包成一个名叫 `features` 的子模块。`nn.Sequential` 是"顺序容器"：数据进来后按书写顺序依次流过每一层，省去手写多层调用的麻烦。**特意把骨干命名为 `features` 单独包起来，是本章的关键结构设计**——这样后面才能方便地整体迁移、整体冻结。
- `nn.Linear(10, 64)` —— 全连接层（线性层）：输入 10 维、输出 64 维。内部做 `y = x @ W.T + b`，权重 `W` 形状为 (64, 10)，偏置 `b` 形状为 (64,)。这些参数会在预训练中被学好，并在微调时被迁移。
- `nn.ReLU()` —— 激活函数，`f(x) = max(0, x)`。把负数压成 0，给网络引入非线性，否则两层线性层叠起来等价于一层，表达能力很弱。
- `nn.Linear(64, 64)` —— 第二个全连接层，64 维映射到 64 维，加深特征加工能力。
- 第二个 `nn.ReLU()` —— 再加一次非线性激活，输出的 64 维向量就是"骨干提取出的特征"。

```python
        self.head = nn.Linear(64, 3)  # 预训练任务的分类头：3 个通用类别
```

- `self.head = nn.Linear(64, 3)` —— 分类头：把 64 维特征压成 3 个数，对应预训练任务的 3 个类别的得分（score，也叫 logit，数值越大表示模型越倾向该类别）。注意此时输出维度是 **3**，因为预训练任务是 3 分类；微调到 2 分类任务时这一层必须换掉，这是本章的核心动作之一。

```python
    def forward(self, x):  # 前向传播
        feat = self.features(x)  # 提取特征
        return self.head(feat)  # 输出预训练任务的类别得分
```

- `def forward(self, x):` —— 定义前向传播（forward），即"数据从输入到输出怎么走"。PyTorch 约定：调用 `model(x)` 时会自动执行 `forward`，不要自己直接调 `model.forward(x)`。
- `feat = self.features(x)` —— 输入 `x`（形状 (batch, 10)）先流过特征提取部分，得到 64 维特征 `feat`（形状 (batch, 64)）。
- `return self.head(feat)` —— 特征再过分类头，输出形状 (batch, 3) 的类别得分。注意 `CrossEntropyLoss` 要求传入的是未经 softmax 的原始得分，所以这里不做任何归一化。

### 模拟预训练数据

```python
pretrained = Backbone()  # 实例化待预训练的模型
```

- `pretrained = Backbone()` —— 创建一个骨干网络实例，取名 `pretrained`（预训练模型）。此刻它的参数全是随机初始化的，接下来要在"通用大数据"上把它训练好。

```python
X_pre = torch.randn(1000, 10)  # 1000 个 10 维样本
```

- `X_pre = torch.randn(1000, 10)` —— 生成形状 (1000, 10) 的标准正态分布随机数，模拟 1000 个 10 维的"通用数据"样本。`randn` 的每个参数是形状的一个维度。

```python
y_pre = (X_pre[:, 0] * 2 + X_pre[:, 1] > 0).long() + (X_pre[:, 2] > 0).long()  # 3 类标签
```

- 这一行人为构造 3 分类标签，拆开看：
  - `X_pre[:, 0]` —— 取所有样本的第 0 维特征，`:` 表示"这一维全要"，结果形状 (1000,)。
  - `X_pre[:, 0] * 2 + X_pre[:, 1] > 0` —— 第 0 维乘 2 加上第 1 维，判断是否大于 0，得到布尔张量（True/False）。
  - `.long()` —— 把布尔值转成整数：True→1、False→0。得到取值 {0, 1} 的张量。
  - `(X_pre[:, 2] > 0).long()` —— 同理，按第 2 维是否大于 0 得到另一个 {0, 1} 张量。
  - 两部分相加 —— 标签取值为 0、1、2，正好 **3 个类别**。
  - 注意：标签依赖于第 0、1、2 维特征，所以数据里确实存在可学习的规律，模型能学到东西；这也是为什么后面微调数据也围绕第 0、2 维构造——保证预训练学到的特征对新任务"有用"，迁移才有意义。
  - 常见坑：`CrossEntropyLoss` 要求标签是 `Long` 类型（整数），所以这里必须用 `.long()` 转换。

```python
pre_loader = DataLoader(TensorDataset(X_pre, y_pre), batch_size=32, shuffle=True)  # 加载器
```

- `TensorDataset(X_pre, y_pre)` —— 把特征和标签打包成数据集，取第 i 条数据时同时返回 `X_pre[i]` 和 `y_pre[i]`。两个张量的第 0 维（样本数）必须一致，否则会报错。
- `DataLoader(..., batch_size=32, shuffle=True)` —— 数据加载器：每次迭代吐出 32 个样本组成一个批次；`shuffle=True` 表示每一轮（epoch，即把整个数据集完整过一遍）开始前打乱样本顺序，避免模型记住样本排列规律。1000 个样本 ÷ 32 ≈ 32 个批次（最后一批不满 32 个，只有 8 个）。

```python
optimizer = torch.optim.Adam(pretrained.parameters(), lr=0.01)  # 优化器
criterion = nn.CrossEntropyLoss()  # 损失函数
```

- `optimizer = torch.optim.Adam(pretrained.parameters(), lr=0.01)` —— 创建 Adam 优化器（一种自适应调整步长的主流优化算法），管理 `pretrained` 模型的**全部**参数，`lr=0.01` 是学习率（每次参数更新的步长）。`pretrained.parameters()` 会返回模型中所有注册层的参数（features 里的两层 Linear 加 head 的权重和偏置）。注意学习率 0.01 对 Adam 来说偏大，预训练数据多、任务简单所以没问题；微调时就要降，后面会看到。
- `criterion = nn.CrossEntropyLoss()` —— 交叉熵损失函数，多分类任务的标准配置。它内部先对得分做 softmax（把得分转成概率），再计算与真实标签的差距，数值越小说明预测越准。它的输入是"原始得分 + 整数标签"，这正是 `forward` 的输出和 `y_pre` 的形态。

### 预训练循环

```python
print("--- 阶段一：预训练（通用数据） ---")
```

- 打印阶段标题，方便在输出中定位进度。

```python
for epoch in range(10):  # 预训练 10 轮
    for bx, by in pre_loader:  # 逐批次
        loss = criterion(pretrained(bx), by)  # 前向 + 损失
        optimizer.zero_grad()  # 清梯度
        loss.backward()  # 反向传播
        optimizer.step()  # 更新参数
```

这是标准的 PyTorch 训练五步法，逐行看：

- `for epoch in range(10):` —— 外层循环：把 1000 个样本完整训练 10 遍（10 个 epoch）。通用数据多、任务简单，10 轮足够收敛。
- `for bx, by in pre_loader:` —— 内层循环：DataLoader 每次吐出一个批次，`bx` 形状 (32, 10)（最后一批是 (8, 10)），`by` 形状 (32,) 或 (8,)。
- `loss = criterion(pretrained(bx), by)` —— 一行干两件事：`pretrained(bx)` 自动调用 `forward` 得到形状 (32, 3) 的得分（前向传播）；`criterion(..., by)` 算出这批数据的交叉熵损失，结果是一个标量张量。
- `optimizer.zero_grad()` —— 清空上一轮残留的梯度。PyTorch 的梯度默认是**累加**的，不清零的话梯度会越滚越大，训练直接错乱。这是新手最常踩的坑之一。
- `loss.backward()` —— 反向传播：从损失出发，自动计算损失对每个参数的梯度（gradient，即"参数往哪个方向改、改多少能让损失变小"），存到各参数的 `.grad` 属性里。
- `optimizer.step()` —— 优化器根据梯度和学习率，真正更新所有被管理的参数。至此一个批次的训练完成。

```python
print("预训练完成，骨干网络已学会通用特征\n")
```

- 打印完成提示，`\n` 是换行符，让后续输出空一行、更清晰。此时 `pretrained` 的 `features` 部分已经学会把 10 维输入加工成"对第 0、1、2 维敏感"的有用特征——这就是待会儿要迁移的"通用能力"。

### 业务小数据

```python
# ========== 3. 第二步：微调 —— 迁移到业务小数据 ==========
# 业务场景：只有 80 个样本的 2 分类任务（数据少，从头训练效果差，微调是最佳选择）
X_task = torch.randn(80, 10)  # 80 个业务样本
```

- `X_task = torch.randn(80, 10)` —— 模拟业务数据：只有 **80 个**样本，比预训练的 1000 个少一个数量级。这是微调的典型处境——业务数据稀缺，从头训练一个网络根本学不好，必须借助预训练模型。

```python
y_task = (X_task[:, 0] + X_task[:, 2] > 0).long()  # 业务标签（2 类）
```

- 构造 2 分类业务标签：第 0 维加第 2 维大于 0 则为 1，否则为 0，取值 {0, 1}。注意两点：一是标签只依赖第 0、2 维特征，与预训练任务关注的维度（0、1、2）有重叠——所以预训练特征对这个任务有用，迁移才能奏效；二是这是 **2 分类**，而原来的分类头输出 3 维，维度对不上，所以分类头必须换。

```python
task_loader = DataLoader(TensorDataset(X_task, y_task), batch_size=16, shuffle=True)  # 加载器
```

- 为业务数据建加载器：batch_size 降为 16（数据少，批次也调小，80 ÷ 16 = 5 个批次），同样打乱顺序。

### 方案 A：冻结骨干，只训练分类头

```python
model_a = Backbone()  # 新建模型
```

- `model_a = Backbone()` —— 新建一个结构相同的模型。此刻它的所有参数都是随机初始化的，下一步把预训练好的骨干参数灌进来。

```python
model_a.features.load_state_dict(pretrained.features.state_dict())  # 把预训练的骨干参数迁移过来
```

- 这是**参数迁移**的关键一行，从右往左读：
  - `pretrained.features.state_dict()` —— 把预训练模型 `features` 部分（两个 Linear 层的权重和偏置）导出为一个字典：`{参数名: 张量值}`。
  - `model_a.features.load_state_dict(...)` —— 把这个字典加载进 `model_a` 的 `features` 部分。
  - 因为两边 `features` 结构完全相同（都来自 `Backbone` 类），参数名和形状一一对应，加载成功。如果结构不同会报 `size mismatch` 或 `Missing key` 错误。
  - 效果：`model_a` 的骨干瞬间"继承"了预训练学到的全部特征提取能力，不用重新学。

```python
model_a.head = nn.Linear(64, 2)  # 换成业务任务的 2 分类头（输出维度必须匹配新任务）
```

- `model_a.head = nn.Linear(64, 2)` —— 直接给 `head` 属性赋一个新的全连接层：64 维输入、**2 维**输出，匹配业务任务的 2 个类别。注意这个新层是随机初始化的，什么都没学过，所以微调阶段主要就是在训练它。
- 为什么不能用 `load_state_dict` 迁移分类头？因为预训练头是 (3, 64) 的权重，新任务要 (2, 64)，形状对不上；而且类别含义也不同，迁过来没有意义。**"留骨干、换头"是所有微调任务（无论 CV 还是 NLP）的通用套路。**

```python
for param in model_a.features.parameters():  # 遍历骨干网络的所有参数
    param.requires_grad = False  # 冻结：这些参数在训练中不更新（赛项考点）
```

- `for param in model_a.features.parameters():` —— 遍历 `features` 部分的所有参数（两层 Linear 的权重和偏置，共 4 个张量）。
- `param.requires_grad = False` —— 把每个参数的"需要梯度"开关关掉，即**冻结**。效果有二：一是反向传播不再为它们计算梯度，省显存省算力；二是优化器更新时它们纹丝不动，预训练学到的特征被完整保留。这是本章的赛项考点之一。
- 注意冻结只作用于 `features`，`model_a.head` 是新创建的层，`requires_grad` 默认为 True，正常训练。

```python
optimizer_a = torch.optim.Adam(model_a.head.parameters(), lr=0.01)  # 优化器只管分类头的参数
```

- `optimizer_a = torch.optim.Adam(model_a.head.parameters(), lr=0.01)` —— 优化器**只接收 `head` 的参数**。这是双保险：即使梯度算出来了，优化器也只会更新它管理的参数。实际工程中只传 head 参数是更规范的做法，能避免误更新、也节省优化器的内存开销。

```python
print("--- 阶段二：微调（冻结骨干，只训练分类头） ---")
for epoch in range(20):  # 微调 20 轮
    for bx, by in task_loader:  # 逐批次
        loss = criterion(model_a(bx), by)  # 前向 + 损失
        optimizer_a.zero_grad()  # 清梯度
        loss.backward()  # 反向传播（被冻结的参数不会产生梯度更新）
        optimizer_a.step()  # 只更新分类头
```

- 训练循环与预训练完全同构（五步法），区别只在数据换成了业务小数据、模型换成了 `model_a`、优化器换成了只管 head 的 `optimizer_a`。
- `for epoch in range(20):` —— 微调 20 轮。业务数据只有 80 条，一轮很快，多训几轮让随机初始化的新分类头充分收敛。
- `loss.backward()` —— 反向传播照常执行，但被冻结的骨干参数不会产生梯度更新（梯度要么不计算、要么被优化器忽略），所以骨干保持不变，只有分类头在学习。
- 每批 16 个样本，`bx` 形状 (16, 10)，模型输出形状 (16, 2)，`by` 形状 (16,)。

```python
with torch.no_grad():  # 评估
    acc_a = (model_a(X_task).argmax(1) == y_task).float().mean()  # 方案 A 准确率
```

- `with torch.no_grad():` —— 评估时不训练，用这个上下文管理器关掉梯度计算，省内存、提速，也避免误改参数。
- `model_a(X_task)` —— 一次性把全部 80 个业务样本喂进模型，输出形状 (80, 2) 的得分。
- `.argmax(1)` —— 沿第 1 维（类别维）取得分最大的下标，即模型预测的类别，结果形状 (80,)，取值 {0, 1}。`argmax` 就是"谁得分高选谁"。
- `== y_task` —— 预测与真实标签逐一比较，得到布尔张量：对为 True、错为 False。
- `.float()` —— 转成浮点数：True→1.0、False→0.0。
- `.mean()` —— 求平均，正好等于准确率（对的占比）。`acc_a` 是一个标量张量。

### 方案 B：全量微调（差异化学习率）

```python
model_b = Backbone()  # 新建模型
model_b.features.load_state_dict(pretrained.features.state_dict())  # 迁移预训练骨干
model_b.head = nn.Linear(64, 2)  # 换分类头
```

- 这三行与方案 A 开头完全相同：新建模型、迁移预训练骨干、换成 2 分类头。两个方案从**同一起点**出发，区别只在训练策略——方案 B 不冻结任何参数。

```python
optimizer_b = torch.optim.Adam([  # 为不同部分设置不同学习率（微调经典技巧）
    {"params": model_b.features.parameters(), "lr": 0.001},  # 骨干：小学习率，避免破坏已学知识
    {"params": model_b.head.parameters(), "lr": 0.01},  # 新分类头：大学习率，快速学习
])
```

- 这是本章第二个赛项考点：**参数组（parameter groups）**。优化器不只接受一串参数，还接受一个字典列表，每个字典里 `params` 指定一组参数，其余键（这里是 `lr`）对该组单独生效。
- 第一组：骨干 `features`，学习率 **0.001**——比预训练时还小一个量级。理由：骨干已经学得很好了，只需根据新业务数据轻微调整；步子太大反而会"灾难性遗忘"（catastrophic forgetting），把辛苦学到的通用特征冲掉。
- 第二组：新分类头 `head`，学习率 **0.01**——它是随机初始化的，从零开始，需要大步快跑才能尽快收敛。
- "新层大步走、老层小步挪"是微调大模型的行业标准做法，真实业务中微调 BERT 等模型时同样如此。

```python
print("--- 阶段二：全量微调（差异化学习率） ---")
for epoch in range(20):  # 训练 20 轮
    for bx, by in task_loader:  # 逐批次
        loss = criterion(model_b(bx), by)  # 前向 + 损失
        optimizer_b.zero_grad()  # 清梯度
        loss.backward()  # 反向传播
        optimizer_b.step()  # 更新所有参数
```

- 循环结构与方案 A 一模一样，但有两个本质区别：一是没有冻结任何参数，`loss.backward()` 会为**所有**参数计算梯度；二是 `optimizer_b.step()` 会按各自的学习率更新骨干和分类头——骨干每次挪 0.001 的步子，分类头挪 0.01。

```python
with torch.no_grad():  # 评估
    acc_b = (model_b(X_task).argmax(1) == y_task).float().mean()  # 方案 B 准确率
```

- 用完全相同的方式评估方案 B 在业务数据上的准确率，保证两种方案的比较公平。

### 输出对比结论

```python
print(f"\n冻结骨干微调准确率: {acc_a:.2%}")
print(f"全量微调准确率:     {acc_b:.2%}")
```

- 这两行用 f-string 格式化输出：
  - `\n` —— 先空一行。
  - `{acc_a:.2%}` —— 把张量值格式化为百分比并保留两位小数，例如 0.8875 显示为 `88.75%`。`:` 后是格式说明符，`.2%` 即"乘 100 加百分号、留两位小数"。
  - 第二行中"全量微调准确率："后面有几个空格，是为了让两个百分数在终端里对齐，纯属排版美观。

```python
print("结论：数据少时冻结骨干更稳；数据较多时全量微调（小学习率）通常上限更高。")
```

- 打印经验结论：两种方案没有绝对优劣，选择取决于业务数据量。本次实验中全量微调数字更高（原因见"运行结果与解读"），但"冻结更稳"这条规律在真实小数据场景（尤其是数据和预训练分布差异大时）经常反过来成立。

## 运行结果与解读

```text
--- 阶段一：预训练（通用数据） ---
预训练完成，骨干网络已学会通用特征

--- 阶段二：微调（冻结骨干，只训练分类头） ---
--- 阶段二：全量微调（差异化学习率） ---

冻结骨干微调准确率: 88.75%
全量微调准确率:     98.75%
结论：数据少时冻结骨干更稳；数据较多时全量微调（小学习率）通常上限更高。
```

逐项解读：

- **`--- 阶段一：预训练（通用数据） ---`** —— 预训练循环开始。循环内部没有打印语句，所以这行标题之后直接看到完成提示，属正常现象，不代表程序卡住。
- **`预训练完成，骨干网络已学会通用特征`** —— 10 个 epoch（共 320 次参数更新）执行完毕。此时 `features` 部分已经学会从 10 维输入中提取与第 0、1、2 维相关的特征。看不到损失数字，如何确认它"学会了"？看后面微调的效果就知道——如果骨干没学到东西，迁移后准确率不可能这么高。
- **`--- 阶段二：微调（冻结骨干，只训练分类头） ---`** —— 方案 A 开始：骨干原封不动，只有新的 2 分类头在 80 条业务数据上训练了 20 轮。
- **`--- 阶段二：全量微调（差异化学习率） ---`** —— 方案 B 开始：骨干以 0.001 的小学习率、分类头以 0.01 的大学习率一起训练。
- **`冻结骨干微调准确率: 88.75%`** —— 80 个业务样本中模型答对 71 个（80 × 88.75% = 71）。这个成绩的意义：分类头是从零随机初始化的，只靠迁移过来的骨干特征、用 80 条数据训了 20 轮就达到近九成准确率——**这正是迁移学习的价值**：如果不用预训练骨干、整个网络从头训练，80 条数据远远不够。
- **`全量微调准确率:     98.75%`** —— 答对 79 个，比方案 A 高 10 个百分点。原因：本实验中业务标签的规律（第 0 维 + 第 2 维）与预训练标签的规律（第 0 维 ×2 + 第 1 维、第 2 维）并不完全一致，骨干特征需要"再调整一下"才能完美贴合新任务。全量微调允许骨干以小学习率微调，所以上限更高，达到了 98.75%。
- **结论行** —— 为什么又说"数据少时冻结骨干更稳"？因为全量微调可训练参数多（本模型约 1 万个），当数据只有几十条时很容易过拟合——在训练集上分数虚高、换个新样本就露馅。本实验在训练集上评估，且 80 条数据对这个小任务还算够，所以全量微调占优。真实比赛和业务中，判断依据是：先用冻结方案做基线，数据量允许、且验证集（模型没见过的数据）表现确实更好时再上全量微调。

**怎样算"学对了"**：你应看到全量微调（98.75%）明显高于冻结骨干（88.75%），且两个数字都远高于随机猜测的 50%。如果两个数都接近 50%，说明预训练骨干没学到有用特征或参数迁移失败；如果冻结方案反而高很多，通常说明全量微调的学习率设大了，把骨干"带偏了"。

## 小结

- 微调 = 预训练模型的"转岗培训"：保留骨干（`features`）学到的通用特征，替换分类头（`head`）匹配新任务的类别数。
- 参数迁移用 `model.features.load_state_dict(pretrained.features.state_dict())`，前提是两边结构完全一致。
- 冻结骨干：遍历参数设 `requires_grad = False`，并让优化器只管理分类头参数——数据少时最稳。
- 全量微调：所有参数都更新，但必须用**参数组**给骨干设小学习率（如 0.001）、给新头设大学习率（如 0.01），防止破坏已学知识。
- 本实验中全量微调 98.75% > 冻结骨干 88.75%，印证了"数据够时全量微调上限更高"；数据极少或预训练与业务差异大时，应优先冻结方案。

## 动手练习

1. **去掉预训练，从头训练**：把方案 A 中迁移参数的那一行（`model_a.features.load_state_dict(...)`）注释掉，让 `model_a` 完全随机初始化后直接在 80 条业务数据上训练。运行后对比准确率，体会"没有预训练，小数据从头训练有多难"。
2. **取消冻结**：把 `param.requires_grad = False` 改成 `True`（或删掉冻结循环），但优化器仍然只传 `model_a.head.parameters()`。思考并验证：此时骨干参数会被更新吗？为什么？（提示：优化器只更新它管理的参数，但梯度照样会被计算——显存浪费。）
3. **调大骨干学习率，观察"灾难性遗忘"**：把方案 B 中骨干的学习率从 `0.001` 改成 `0.1` 再运行，观察全量微调准确率是上升还是下降，理解"老层小步走"的必要性。
